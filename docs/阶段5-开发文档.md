## 1. 目标与退出条件

阶段 5 在补齐「自由表格」「已搁置状态」「账号认领」三项产品能力的基础上，将字幕组正在使用的真实 23 张历史 Excel 工作表保真、幂等、无损地迁入正式工作台并完成香港 VPS 线上切换，让全组可立即停用旧共享表格、转入正式在线协作。

退出条件（全部满足才算完成，逐条对应第 11 节验收清单）：

1. **自由表格与「通用文档」在线表格（产品能力 1）**：支持在新建工作表弹窗选择 **「自由表格（空白文档）」** 模板（去掉标题/优先级/发布状态/分工说明/文件等任务固定列，所有列均可自由增删改名调序，复用 Teable Canvas Grid 实时协同与修改记录，**绝不进入首页看板与「我的任务」**）；「通用文档（`/docs`）」升级为双模式（顶部轻量标签切换：**各在线表格** + **公共文件** + `+ 新建表格`），打开 `/docs` 首屏即呈现可在线协作编辑与检索的 `⭐翻译对照表⭐`（按 4 个分区横幅清晰分组），切到「公共文件」可完整使用阶段 3/4 的 R2 与多网盘公共资源。
2. **「已搁置（`shelved`）」状态闭环（产品能力 2）**：`publishStatus` 扩展为 `unpublished | published | shelved`（未发布 / 已发布 / 已搁置）；`published` 与 `shelved` 均不上首页看板、不出现在「我的任务」进行中/待开始列表；工作表顶部在 `已发布（N 条）` 折叠条右侧并列展示默认折叠的 `已搁置（M 条）`（无搁置项时自动隐藏），工作表单元格与详情侧栏均可随时切换与重新激活；`fast-check` 属性测试锁定 `shelved` 与 `free` 工作表零泄漏至看板。
3. **待认领用户与一次性认领链接（A14 替代方案，产品能力 3）**：支持预创建 `login_name = NULL, claimed_at = NULL` 的待认领用户并直接关联至任务工序格；管理员在 `/admin/users` 页面可见每个待认领用户的链接状态（「未生成 / 有效至 YYYY-MM-DD / 已过期」）并支持一键 **「生成 / 重新生成认领链接」**（默认 30 天有效，重生成自动作废旧链接，无需手动改库）；用户打开 `/claim/:token` 自设登录名、密码并确认显示名后立即登录，原归属的全部历史/进行中任务立刻出现在「我的任务」中；令牌严格零泄漏。
4. **专表专办 OOXML 解析与 23 表规则映射（A10 / R13）**：通过 `xl/workbook.xml` + `xl/_rels/workbook.xml.rels`（绝不按 ZIP 顺序）与 `styles.xml`/`theme1.xml` 精确解析填充/字体 RGB、隐藏行、合并单元格、超链接与数字格式；完整落地第 7 节全部 23 张表的专表规则（含 12 制作表 → 4 杂项自由表 → 6 留念自由表顶栏排序、`⭐翻译对照表⭐` 进 `/docs`、原版 `.xlsx` 进 `/docs` 公共文件、`长视频全熟` 2 条百度网盘分享文本自动转为作品共用网盘资源、25 组人名去重合并、精确 `na` 词表与括号备注提取、含糊/无色单元格绝不静默判为 `done`）。
5. **严格幂等重跑与差分测试 Oracle（A10 / R13）**：基于脱敏合成小样（`apps/server/test/fixtures/import/workbook-sample.xlsx` + `workbook-oracle.json`）通过逐行差分测试（维护显式归一化白名单：Unicode NFC、`\r\n → \n`、首尾空白清理），并验证同一工作簿连续导入 2 次数据库状态零漂移；原始 `.xlsx` 经 `StorageDriver` 存为不可变只读备份并记入 `import_batches`。
6. **香港 VPS 正式数据切换与验收**：备份旧测试库后执行受控清空（仅保留初始管理员 `1zero`），迁入真实 [无名字幕组任务分划.xlsx](file:///C:/work/worksheet/%E6%97%A0%E5%90%8D%E5%AD%97%E5%B9%95%E7%BB%84%E4%BB%BB%E5%8A%A1%E5%88%86%E5%88%92.xlsx)（23 表）并核对每张表行数、作品横幅、看板卡片、搁置折叠条、待认领用户数、`1zero` 管理员绑定、翻译对照表与原版备份文件；CI 全绿、桌面（1440×900）与手机（390×844）均正常，同机原有站点无影响。

### 5.2 任务「已搁置（`shelved`）」状态

1. **状态语义**：
   - `unpublished`（未发布）：活跃制作中，按既有规则进入首页看板与「我的任务」；
   - `published`（已发布）：制作完成并已发布，离开首页看板与「我的任务」待办，收起在工作表顶部 `已发布（N 条）` 折叠条；
   - `shelved`（已搁置）：因取消、撞车（已有汉化）或暂缓而搁置，**离开首页看板与「我的任务」待办**，收起在工作表顶部 **`已搁置（M 条）`** 折叠条（与 `已发布` 折叠条并列，M = 0 时隐藏不占位）。
2. **展开与恢复**：
   - 点击 `已搁置（M 条）` 折叠条可展开查看搁置任务、备注与历史分工，随时在工作表「发布」列或 `TaskDetailDrawer` 切回「未发布」重新激活（实时同步至所有在线用户的表格与首页看板）；
   - 带 `?taskId=` 跳转指向已搁置任务时，自动展开 `已搁置` 折叠区并滚动高亮，逻辑与 `已发布` 完全对称。

### 5.3 待认领用户与一次性认领链接

1. **核心状态机**：
   - **待认领（`claimed_at IS NULL`）**：`login_name = NULL`、`password_hash = NULL`，无法通过 `/login` 登录；已在项目 `memberships` 中拥有 `role = 'user'`，可以直接被选为工序负责人、展示在工作表/看板/筛选中；
   - **认领链接签发（`POST /api/users/:id/claim-link`）**：
     - 仅 `users.manage` 管理员可调；目标用户须属当前项目且 `claimed_at IS NULL`（已认领用户返回 `409 CONFLICT`）；
     - 在数据库事务内将该用户此前所有未使用且未作废的 `account_claims` 置 `revoked_at = NOW()`，插入新的 `token_hash`（默认 30 天有效，允许传 `ttlDays: 1..90`），返回明文一次性链接 `${appOrigin}/claim/${token}` 与 `expiresAt`；
     - **过期/丢失零运维重发**：管理员在 `/admin/users` 中看到链接状态为「未生成」「有效至 YYYY-MM-DD」或「已过期」，点一下「生成认领链接」或「重新生成」即可立即拿到新链接，绝无需手改数据库；
   - **用户认领（`/claim/:token`）**：
     - `GET /api/account-claims/:token`（`public` + IP 限速）：校验 token 存在、未用、未作废、未过期且目标用户未认领，返回 `{ displayName, projectName, role, expiresAt }`；任意异常统一返回 `404` + `认领链接无效或已过期，请联系管理员`（不区分不存在/已用/过期）；
     - `POST /api/account-claims/:token/complete`（`public` + IP 限速）：接收 `{ loginName, displayName?, password }`，在 `withTx` 事务内锁住 `account_claims` 与 `users` 行，复验未用/未作废/未过期/未认领、校验 `loginName` 格式与全局唯一、校验 `password !== loginName` 与强度（≥ 8 位）、若修改 `displayName` 校验唯一，写入 `loginName / displayName / passwordHash / claimedAt = NOW()`，标记 `usedAt = NOW()` 并作废该用户其余未用认领记录，立即创建登录会话写 Cookie，广播 `user.updated`，返回 `MeResponse` 跳转首页 `/`；
   - **登录与密码重置防护**：
     - `POST /api/users/:id/password-reset` 遇到待认领用户时返回 `409 CONFLICT`（“该用户尚未认领账号，请生成认领链接”）；
     - `/admin/users` 页面对已认领用户展示「重置密码」按钮，对待认领用户展示「生成认领链接 / 重新生成」按钮。

## 7. 23 张历史工作表专表专办映射规范

以下规则全部基于对真实文件 [无名字幕组任务分划.xlsx](file:///C:/work/worksheet/%E6%97%A0%E5%90%8D%E5%AD%97%E5%B9%95%E7%BB%84%E4%BB%BB%E5%8A%A1%E5%88%86%E5%88%92.xlsx) 的逐表 OOXML 实查制定（全簿 0 条条件格式），按最终展示顺序编排。

### 7.1 统一解析与归一化规则（显式白名单）

1. **Sheet 严格配对**：通过 `xl/workbook.xml` 的 `r:id` 查 `xl/_rels/workbook.xml.rels` 获取目标 XML 路径，绝不按 ZIP 文件序号匹配。
2. **颜色解析**：解析 `xl/theme/theme1.xml` + `xl/styles.xml` 的 `rgb`、`theme + tint`、`indexed`，忽略纯白 `#FFFFFF` / 默认底色：
   - **绿色系（已完成）**：`#92D050`、`#A1CE63`、`#C3EAD5` → 工序格判 `done`；
   - **黄色系（进行中）**：`#FFC000`、`#FEFB54` → 工序格判 `in_progress`；
   - **蓝色系（漫画表专用）**：`#8CDDFA` → 按漫画表图例“蓝色为进行中”判 `in_progress`；
   - **灰色系（搁置）**：`#939393`、`#BFBFBF`、`#D8D8D8`（整行或整块置灰）→ 任务标 `publishStatus = 'shelved'`，保留原内容与备注；
   - **无色单元格**：即使填了负责人姓名，也**严格判为 `not_started`（绝不静默判为 `done`）**。
3. **日期与时长不猜测**：
   - `numFmtId` 对应日期格式（如 `yyyy/m/d`、`yyyy"年"m"月"d"日"`、`m"月"d"日"`、内建 14–22 / 72）的整数序列号 → 按 Excel 1900 纪元（含 1900 闰年偏移）精准转为 `YYYY-MM-DD`；文本日期 `2024.09.21` / `2025.11.7` / `2025.06..22`（纠错双点）归一化为 `YYYY-MM-DD`；无法形成单个合法公历日期的值（如 `2023.11.06-20`、`\`）保留原值进备注或文本列，不强塞进 `publishedAt`；
