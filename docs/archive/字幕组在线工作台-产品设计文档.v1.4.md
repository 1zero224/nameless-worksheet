# 无名字幕组在线工作台：产品设计文档

版本：v1.4 · 修订日期：2026-11-15 · 研究日期：2026-11-08 · 状态：阶段 0 技术可行性验证已完成；正式产品待从阶段 1 开始全新开发

> **给开发 AI 的执行说明：** 本文是正式产品的需求与开发依据，应可脱离原型源码独立使用。现有 `app/` 只承担阶段 0 技术验证，用户明确不以这版源码作为开发基础；请建立新的正式工程，不沿用其代码、数据库、接口契约或页面布局作为既定架构。阶段 0 的选型结论和经验已汇入本文第 13.3 节，无需先接手或修复旧原型。正式工程的初始化、版本锁定、数据库迁移和 CI 随阶段 1 一并建立，并对新实现执行对应回归验收。阶段 0 完成不等于正式产品或上线验收完成。

## 1. 产品结论

建设一个接近现有共享工作表的在线工作台：成员填写分工与进度，在具体任务上上传文件或填写一个/多个网盘链接。上传的文件保存到 Cloudflare R2，任务内直接展示最新版本，并能展开历史版本查看、下载旧文件。

核心规则是：**新版本保存成功后直接成为最新版本，旧版本文件保留。** 更新文件无需审核，也不另设“当前采用版本”。制作各环节存在时间差，小幅修改和协作沟通继续在群里完成。

长视频分工沿用表格方式：成员可自由填写 P1、前半、00:00–13:00 等分工说明，按需要手动增加行。系统不负责切块、时间区间校验、依赖追踪或合稿管理。工作台不设置截止日期，不提供讨论、评论和交接记录。

已确定采用组件自建的专用轻应用：主界面使用 shadcn/ui，任务表使用 TanStack Table，上传使用 Uppy，文件存储使用 Cloudflare R2。参考 Teable/Baserow 的表格与附件体验、Plane 的任务详情、Nextcloud/Frame.io 的文件历史呈现。产品重点是把进度和文件放到一起，降低查找成本。

## 2. 研究方法、证据范围与限制

本次读取本地 XLSX 的 OOXML 工作簿关系、全部工作表的单元格数据，并检查代表性表头、说明和任务行；读取 TXT 文件树及代表性目录。未修改原始两个文件，未访问群文件实际内容，未下载群内资源，未验证任何现存网盘链接。颜色、条件格式、嵌入图形和所有合并单元格的视觉语义没有逐一复原，不能由姓名或空白值推断真实完成状态。

互联网研究覆盖在线表格、任务管理、影视制作管理、文件管理、上传基础组件和专业审片六类方向，选出下文 12 个项目/产品。功能判断以官方文档和官方仓库为依据；其中 Zou 与 Uppy 下载了浅克隆并检查关键源码。其他项目属于文档与许可层核验，未部署运行，不能把官方商业版本功能视为社区版已验证功能。搜索结果可能带有抓取滞后，落地时需锁定具体版本再做集成验证。

本地证据：`无名字幕组任务分划.xlsx`、`group_file_tree_686700411.txt`。结构化提取在 `research/workbook-summary.json`；源码在 `research/zou` 和 `research/uppy`。

阶段 0 于 2026-11-09 完成主要本地技术实验，2026-11-15 复核并整理为正式开发输入。第 13.3 节区分原始报告支持的结果、早先观察到但报告已被覆盖的结果和未验证事项。原型的本地测试不代表成员设备、生产环境或完整业务验收；本文记录的版本号是实验基线，并非要求新工程照搬全部依赖。

## 3. 现状发现与设计影响

### 3.1 工作表不是单一视频任务清单

工作簿实际有 23 个工作表。通过 `xl/_rels/workbook.xml.rels` 对照 sheet ID 与文件路径后，确认包含：首页、歌曲翻译、BD评论音轨、长视频全熟、总集篇、切片熟肉、广播剧、中短视频、杂志、漫画、刺刺广播2025-2026、周报、直播与转播、⭐翻译对照表⭐、相关收益、赞助奖品清单、2025除夕抽奖奖项，以及六张留念表。提取时不能按 ZIP 文件枚举顺序配对表名。

| 已观察到的资料 | 原文位置/例子 | 对产品的影响 |
|---|---|---|
| 各类别的工序不同 | 歌曲翻译 A2:K2 有日文歌词、全曲翻译、校对、润色；杂志 A1:I1 有嵌字/排版 | 提供制作模板，不固定一套视频工序 |
| 长视频按时间段分工 | 长视频全熟 B2:K2；BD评论音轨 C3:C6 为 0-6、6-12、12-18、18-24 | 保留表格式分工说明和手动增行，不建立专门分段对象或自动校验 |
| 总集篇依赖跨文件参考 | 总集篇 K2 提及音源在群文件、动画字幕合集、30分钟一段、新内容留空等 | 任务可将原片、参考资料和字幕等文件分类挂载，成员自行选择所需文件 |
| 阶段多人协作与不适用 | 表内存在多人姓名、官中、不用翻、斜杠等 | 多负责人；另设“不适用/无需制作”，不得当成未完成 |
| 进度部分依靠颜色 | 漫画 A2、留念表说明有绿/黄/蓝和红字优先语义 | 状态与优先级结构化；导入颜色须人工映射确认 |
| 辅助内容混在工作簿 | 翻译对照表、收益、奖品等 | 术语/参考资料独立入口；财务和奖品暂留原工具，避免扩大范围 |

这里的行数只反映 XML 行节点，不等同任务数量。留念表也不能全部认定为已发布。第一版不输出未经逐行清洗的“任务总数”。

### 3.2 群文件已经承担了版本库的职责

TXT 头部报告 1,097 个文件、15.9 GiB。这是目录导出器统计，未按文件字节复算；也不包括尚未传群或仅在网盘的资源。

可直接观察到：`5th-BD` 下同时有空轴、待校全篇、待校前13分钟和全场熟肉 ASS；`rockinjapan vlog` 下有待轴、待校、已校文本/字幕及原始 MP4；目录存在同名 `朱李.mp4` 两条，翻译考核文件有多个 v2、（新）及同名记录。没有哈希和内容，不能确认同名文件是否相同，也不能把“前13分钟”自动归并成“全篇”的历史版本。

文件类型覆盖 ASS、SRT、TXT、MP4、音频、PSD 等。资源模型必须容纳字幕、工程文件、字体、图片、音视频和压缩包，预览能力则按格式分级。

## 5. 用户、目标与范围

主要角色：统筹维护工作表和成员分工；成员填写进度、下载和上传文件、维护网盘入口；管理员管理成员、配额、回收站和备份。校对、终校仍是表格里的制作工序和人员分工，不是系统的版本审核角色。

目标：从工作表直接找到任务文件；清楚看到谁在做、进度如何；默认展示最新版本，历史文件随时可下载；同一资源支持 R2 与多个网盘入口；分工形式接近原表。

MVP 包含：邀请加入、项目与分类工作表、任务行、可配置工序列、多负责人、手动状态、自由分工说明、任务文件侧栏、R2 上传下载、多网盘链接、文件版本历史、基本搜索、导入预览、导出与回收站。

明确排除：版本审核与退回、当前采用版本及输入版本追踪、自动切块和分段校验、依赖与合稿管理、截止日期与逾期提醒、讨论评论与交接记录。这些不列入后续阶段。在线字幕编辑、网盘账号托管和自动跨盘搬运也不属于首版。

## 6. 信息架构与主要页面

### 6.1 导航

左侧：我的任务、项目工作表、资源检索、参考资料、归档；管理员另见成员与存储。按类型或系列组织工作表，延续多 Sheet 的习惯。

### 6.2 工作表首页

一行表示一个任务或一项手工填写的分工；可增加“所属作品/分工说明”列，将同一长视频的多行放在一起。冻结标题列，默认列为标题、分工说明、各工序负责人及状态、文件、优先级、发布信息。工序列按类别配置，状态同时用文字和颜色展示。

例如，原表中的 P1、P2 或 0-6、6-12 可以原样填写。系统将这些作为普通文本，不切视频、不判断重叠或遗漏、不自动分派。负责人可多选；临时调整继续通过群聊沟通，再手动更新表格。

筛选：我的、未开始、进行中、已完成、已发布、按成员/类型。文件列展示附件数量和最新更新时间，点击打开任务文件侧栏。发布日可作为已有事实保留；不设置计划完成日、截止日或逾期状态。

### 6.3 任务文件侧栏

顶部展示标题、自由分工说明、工序负责人和状态。文件区按原片、字幕、参考资料、成品等分类，可直接下载或打开网盘。移动端改全屏详情。

```text
长视频全熟 / 5th-BD 花絮
分工说明：P1 00:00–13:00（手工填写）
校对：成员甲        进度：进行中
原片 [下载/打开网盘]
校对稿 v3 · 最新 · 成员甲 · 上传时间
[下载] [打开网盘] [上传新版本] [版本历史]
[添加文件] [添加网盘链接]
```

### 6.4 文件卡片与版本历史

卡片显示资源名称、分类、最新版本号、上传者/时间、原文件名和大小。点击“版本历史”按版本倒序展示各版文件及对应入口，能下载任意保留的旧版。版本说明为可选的简短文件说明，不作为讨论区或交接记录。

上传时选择“新建文件资源”或“给现有资源上传新版本”。不得仅凭同名把两个不同资源合并。新版本在上传和完整性校验成功后立即成为最新版本，界面无需审核或人工采用操作。

任务页上传自动关联当前任务；全局上传须先选目标任务。资源可附 R2、百度、夸克、Google Drive 等多个入口，每个入口分别维护 URL、提取码和可选有效期。

|---|---|
| Project / Membership | 项目、成员与访问权限 |
| Worksheet / ColumnConfig | 分类工作表、工序列与显示配置 |
| TaskRow | 标题、所属作品文字、自由分工说明、工序负责人/状态、优先级、来源与发布信息 |
| Artifact | 关联任务的一项逻辑资源，如原片、字幕、字体包、成品；保存分类与最新版本引用 |
| ArtifactVersion | 保留的文件版本；版本号、上传者、上传时间、原文件名、可选说明与大小 |
| Blob / UploadSession | R2 key、内容类型、可选摘要；上传会话、分片状态与预留额度 |
| ResourceLocation | 某一版本的 R2 或外部网盘入口；URL、提取码、可选有效期与可用性信息 |

不建立 Segment、Review、Adoption、Comment、交接事件或输入版本绑定实体。任务自由说明即可表达长视频分工；文件资源的 latest_version_id 仅表示最新保存成功的版本，不承载审核或采用含义。

版本号在同一资源内递增并由数据库分配。两个成员同时上传分别保留为新版本，不能覆盖旧字节；重复完成请求只产生一个版本。尚在上传或校验失败的文件不改变最新版本。

同一版本可挂多个镜像入口，内容不同的文件应另建资源或新版本。无法确认同一内容时标注说明，不声称哈希一致。网盘文件夹可作为资料合集入口，其内容由网盘维护；仅登记链接无法保留网盘端已被删除或覆盖的文件字节。需要本系统保证可下载的历史文件，应实际上传到 R2。

## 8. 使用流程与状态规则

1. 统筹创建分类工作表，按原表配置标题、分工说明、时轴、翻译、校对、后期等列。
2. 成员或统筹填写负责人和进度；长视频需要几行分工，由成员自行增加和描述。
3. 打开任务文件侧栏，直接下载最新文件或打开网盘；需要旧文件时展开版本历史。
4. 上传新的文件资源，或给现有资源上传新版本。保存成功后立即更新最新版本，旧版仍可查看、下载。
5. 给资源补充一个或多个网盘入口，维护提取码和链接信息。
6. 成员自行更新制作状态；文件上传和制作状态互不强制联动。发布后可手工填写已发布状态与发布链接。

制作工序默认状态为未开始、进行中、已完成，另可标“不适用”。发布状态单独手工维护。校对、终校表示实际工作内容，系统不据此审批文件版本。

系统不跟踪成员下载了哪版输入，不发送上游版本变化确认，不要求发布绑定文件版本，不检查各段是否齐全。成员依据最新文件和群内沟通开展工作。小幅修改在群里沟通即可，无需补填讨论或交接记录。

## 9. 网盘链接设计

“支持各种网盘”的 MVP 含义是允许登记任意合法 HTTP/HTTPS 分享地址，展示和跳转；并不承诺各网盘统一登录、直链下载、在线播放或自动查有效性。优先识别百度、阿里/夸克、天翼、115、Google Drive、MEGA、OneDrive；未知域名归为“其他”，识别失败不拒绝合法链接。

支持粘贴带提取码的分享文本，解析后给用户确认；可手工修改名称、URL、码、失效日期。一个版本可有多个网盘入口，也可同时有 R2。打开链接和复制提取码分开，提供“复制完整分享信息”。链接为文件还是文件夹必须明确。

验证状态为未检查、人工可用、人工失效、未知；“上次可用”附时间，不声称永久有效。首版只接受成员报告，不服务器随意抓取用户 URL；未来引入自动检测要限制目标、跳转和内网地址。网盘密码与链接按同一访问权限控制，不进公开日志、通知正文和公开搜索。

## 10. R2 存储与大文件上传

采用私有 R2 bucket。前端向业务 API 申请上传会话，后端核验成员权限、任务、文件大小和剩余额度，生成随机且不可复用的对象 key，再返回短期签名上传能力。浏览器直接上传 R2；业务服务处理元数据，不承担整个视频的中转。预签名 URL 使用 S3 API 域名；不能当作自定义域的永久链接。[R2 预签名文档](https://developers.cloudflare.com/r2/api/s3/presigned-urls/)

小文件单次 PUT，大文件建议采用 Uppy S3 分片模式；100 MiB 可作为初始分界，实际分片大小与并发根据网络测量调整，不直接写死组件内部默认值。CORS 仅允许产品域名与所需方法/请求头，并暴露 ETag；CORS 不代替访问授权。[R2 CORS](https://developers.cloudflare.com/r2/buckets/cors/)、[Uppy S3](https://uppy.io/docs/aws-s3/)

完成流程：创建会话 → 分片签名与上传 → 服务端核对分片归属并完成合并 → HEAD/大小校验 → 幂等地提交版本。上传中、校验中、已保存、失败分别展示；100% 传输不代表已交付。服务端必须确认对象与当前会话匹配，不能信任客户端随意传回的 key、大小、ETag 或任务 ID。ETag 不能一律当作文件内容哈希。

需要持久化 uploadId、objectKey、partNumber、ETag 和会话过期时间；短暂断网只重传失败分片。刷新后可恢复会话，但可能需用户重新选择同一个本地文件，校验后续传，不承诺浏览器关掉后后台继续传。暂停、取消、重试明确；取消后 abort 分片并释放预留额度；定时清理未完成上传和无数据库引用的孤立对象，采用宽限期避免误删。

官方限制按研究日期：对象上限列为 5 TiB，单次上传 5 GiB，最多 10,000 分片；Limits 页面对 multipart 最大上传另给出 4.995 TiB，而上传指南有概括性 5 TiB 表述。产品不得把理论最大值当成首版承诺，建议初始应用上限 20 GiB、管理员可调，超过时保留网盘入口。20 GiB 仍是候选配置，未实测通过；阶段 0 已获得本机小文件、128 MiB API 分片及早先 1 GiB 浏览器实验结果，证据边界见第 13.3 节。阶段 4/6 必须在新实现与成员网络下验证并确定实际启用上限。[R2 Limits](https://developers.cloudflare.com/r2/platform/limits/)、[上传指南](https://developers.cloudflare.com/r2/objects/upload-objects/)

预览：ASS/SRT/TXT 提供安全转义的只读文本；图片按可解码格式显示；音视频仅对浏览器支持的编码直接播放，失败提供下载/网盘入口。PSD、字体、压缩包等显示元数据和下载。ASS 文本预览不等同特效渲染；GBK/UTF-8 等检测失败时提示选择编码，不覆盖原字节。转码代理、字幕差异比对留后续。

## 11. 权限、文件保留与备份

默认邀请制，访客不能读取私有任务与资源。成员在授权项目内填写任务、上传版本和维护入口；管理员维护成员、存储与回收。不存在审核人、版本采用或退回权限。接口必须核验任务和文件所属项目，防止通过修改 ID 跨项目读写。

下载时业务 API 授权后签发短期 GET 地址，默认建议 10 分钟可配置；文件以下载方式提供，危险类型不在站点同源执行。撤权后停止签发新链接，已发短期链接可能在过期前继续有效。首版不提供公共外链。

表格更新使用记录修订号/条件更新，冲突时提示重新加载并保留未提交输入。文件版本列表保留上传者与时间；不建设面向成员的讨论、交接或活动流。基础设施的安全/故障日志仅用于运维，不能演变为额外业务填写要求。

删除默认进入回收站，建议保留 30 天。旧文件版本默认保留，删除历史版本需显式操作；删除最新版时明确提示，并将仍保留的最高版本显示为最新。对象物理清理前检查其他引用与回收期，避免误删共用资源。文件夹型网盘链接的历史内容不由本系统保证。

数据库每日备份；R2 对象另做备份/导出与恢复演练。导出工作表、文件版本与入口关联清单，提取码仅对有权导出的成员包含。

## 12. 迁移方案

1. 保留原始 XLSX/TXT 只读备份；为每条导入记录保留源文件、Sheet、单元格/行范围与批次 ID。
2. 按实际 sheet 关系解析，逐表选择标题行和字段映射；支持先预览再确认，不将首页/术语/财务表当作制作任务。
3. 还原合并单元格的父级归属。只在已确认父级字段向下继承，阶段姓名和状态空白不自动填充。Excel 日期序列、时间分数和文本时间分别转换，保留原值；不从 0.46875 一类值直接猜测是日期还是时长。
4. 每表选择颜色与状态映射，区分“完成未发布”“已发布”“部分完成”“优先级”；有条件格式时结合其实际规则。存疑记录进入人工确认列表，不能凭姓名存在就设完成。
5. 群文件树先进入待匹配资源清单。目录、关键词和集数只提供建议；用户确认作品、范围和角色。相同文件名保留不同来源条目，有实际内容摘要后才判断是否可复用字节。
6. TXT 只有目录线索，不能直接搬运文件。成员后续选择实际文件上传，或补网盘链接，才能形成可访问入口；未拿到文件的条目显示“待补资源”。
7. 先选一个正在做的长视频/广播任务试运行，覆盖手填分工、文件更新和历史下载；旧表同时只读核对，避免长期双写。确认后分批迁移活跃任务，留念表按归档处理。

导入需幂等：同一源批次重复执行不创建重复任务；重新导入差异先预览，不覆盖在线新增交付。导入记录保留批次与来源，不伪装成原始文件上传者和上传时间。

## 13. 技术边界与成本

推荐模块：Web 前端（表格、任务侧栏、上传队列）+ 业务 API（权限、文件版本、签名、表格读写）+ 关系数据库（关联与事务）+ 私有 R2（对象）+ 后台作业（过期上传/配额对账/备份）。前端采用 React 组件体系，应用框架、后端和数据库具体产品在实施时再选，不因使用 R2 强迫全部业务运行在 Workers。小型实例即可起步，实际容量需基准测试。

### 13.1 已确定的前端组件选型

技术路线已确定为组件自建，不以完整在线表格或任务管理产品的 fork 作为底座。

| 层次 | 已选组件 | 职责 |
|---|---|---|
| 主界面 | shadcn/ui | 导航、按钮、人员与状态选择、表单、弹窗、任务文件侧栏、版本历史展示 |
| 任务表 | TanStack Table | 任务行与工序列组织、排序、筛选、列显示、固定标题列和列宽调整；具体单元格由业务组件渲染 |
| 文件上传 | Uppy | 文件选择、上传队列、进度、失败重试和 S3 兼容分片上传；接入业务后端签名后直传 R2 |
| 文件存储 | Cloudflare R2 | 保存最新与历史版本的实际文件字节，通过授权入口访问 |

主界面统一使用 shadcn/ui 的组件与样式体系。任务表直接组合人员、状态和文件入口，不引入 Glide Data Grid 作为首版网格。shadcn/ui 的底层组件方案及各库具体版本在实施时统一锁定。

首版交互约定：

- 工序单元格合并展示负责人和文字状态，点击后通过小面板修改；支持多负责人。
- 标题与自由分工说明支持直接编辑；修改失败时保留输入并提示重试。
- 文件单元格显示可识别的文件名称/最新版本及文件数量，点击打开文件侧栏。
- 侧栏以最新文件为默认入口，提供下载、多个网盘链接、上传新版；历史版本折叠展示。
- 提供“全部”“我的任务”“进行中”等快捷筛选，以及必要的排序、固定标题列和列宽调整。
- 首版不扩展为完整电子表格编辑器，多格填充、复杂选区、公式和完整 Excel 式操作不列为上线前提。

TanStack Table 提供表格逻辑，单元格编辑、样式与业务操作由应用实现；Uppy 负责上传过程，权限、配额、上传会话、完成校验和文件版本保存由业务后端实现。多人编辑同步和冲突处理也由业务层负责。

组件参考：[shadcn/ui](https://ui.shadcn.com/docs)、[TanStack Table](https://tanstack.com/table/latest/docs/overview)、[Uppy S3](https://uppy.io/docs/aws-s3/)。

### 13.2 存储与运行成本

R2 Standard 官方标价为 $0.015/GB-month，A 类 $4.50/百万次，B 类 $0.36/百万次，出网免费；免费额度只适用于 Standard：10 GB-month、A 类 100 万、B 类 1000 万/月。业务成本仍包括数据库、应用、备份和可选转码，不应宣传成全站免费。[官方价格](https://developers.cloudflare.com/r2/pricing/)

以下仅为稳定存储整月、按十进制 GB、扣除 10 GB 免费额度的容量算例，不含请求取整、其他服务、税费和汇率：100 GB 约 $1.35/月；1,000 GB 约 $14.85/月。保留三个完整视频版本可能接近三倍容量，字幕小文件历史通常不是主要容量来源。TXT 的 15.9 GiB 不是整个平台容量预测。

设置项目和成员额度、上传前预留、完成后实扣、取消释放，显示实际用量与预计占用；达到阈值通知管理员。首版优先 Standard，低频层的取回/最短存储等条件需单独估算。

### 13.3 阶段 0 已验证结论与正式开发约束

**结论：React + shadcn/ui 基础方案 + TanStack Table + Uppy + 私有 R2 的技术路线可行，阶段 0 已完成。** 正式产品从新工程的阶段 1 开始；保留实验结论，不把验证原型当作产品底座。后端框架、生产数据库和部署方式仍按正式工程需求选择；原型使用 Fastify 与 Node 内置 SQLite 仅证明最小 API/持久化链路可运行。

#### 实验基线与环境

- 环境：Windows、本机网络、Chromium 158.0.8127.18；桌面 1440×1000 与移动视口 390×844。移动视口不等于手机实机；网络运营商、物理接入与代理路径未独立核实。
- 组件基线：TanStack Table 8.21.3；Uppy Core 5.2.0、Dashboard 5.1.1、AWS S3 插件 5.1.0；AWS SDK S3 与预签名包均为 3.1164.0；hash-wasm 4.13.0。这些是已实验组合，不是最新版本声明。正式开发需锁定兼容版本；更换主版本时按该版本官方 API 重新集成与回归，不能混用不同代的 Uppy 签名回调示例。
- shadcn/ui 实验采用 Radix、Tailwind 与源码组件模式，验证最小按钮/弹层组合；未验证完整组件集。React/Vite、Fastify、Node SQLite 和本地 CI 配置均为原型环境，不自动成为生产架构要求。

| 仓库与 CI | 原型有独立 Git 初始化、依赖锁文件和最小 CI 配置 | 无首个提交、无远程 CI 成功记录；正式工程需重新建仓库结构、迁移与可执行 CI |

本节已包含供新开发者使用的关键结论；上述本地路径只供审计追溯，不要求提供或复用原型源码。原始 JSON 优先于摘要；早先观察结果不能冒充当前仍保留的成功报告。

#### 从验证转化的实现要求

1. 浏览器直接向私有 R2 上传；后端持有密钥，校验权限并签发短期能力。CORS 配置必须覆盖实际前端来源、所需 GET/HEAD/PUT 与请求头，并暴露 ETag；不得把 CORS 当成员鉴权。
2. 可采用已实验的初始参数：超过 100 MiB 分片、每片 20 MiB、并发 3、签名有效期 10 分钟；参数应集中配置，按成员网络与上限调整。20 GiB 只作候选应用配置，不是已验证承诺。
3. 完成由服务端根据会话绑定的 key、ListParts 和 HEAD/大小核验后幂等提交；客户端显示上传 100% 不能直接生成版本。ETag 不能作为全文件 SHA-256；实验的下载摘要一致也不等于服务端已验证全文件摘要。
4. 刷新续传需持久化会话，重选文件后校验身份，再用 ListParts 复用已完成分片。原型使用分块 SHA-256，避免整文件入内存；正式实现必须展示指纹进度/失败、允许取消，并避免指纹阶段长时间无反馈。浏览器关闭后不承诺后台续传；相同大小的不同内容不得误恢复。
5. 已取消、已保存或过期会话不得使重传永久失败；应清理本地失效映射并提示重新开始。取消以服务端 abort 结果为准，失败必须提示；额度释放属于正式业务事务。
6. 新工程必须另行实现成员/项目鉴权、ArtifactVersion 与历史字节保留、不可覆盖最终对象、额度预留/结算、并发与幂等事务、过期会话及孤儿清理。原型无这些保障，不可直接公开部署或迁移其数据库视为正式业务数据。

#### 留给后续阶段的验收

阶段 0 在技术可行性层面结项；不再把下列工作作为重新开启阶段 0 的前置条件：阶段 1 建立正式工程与权限骨架及 CI；阶段 2 回归中文编辑、冲突与真实输入法；阶段 4 在新实现验证断网/失败重试、刷新重选、私有下载、取消和版本事务，并覆盖指纹超时；阶段 6 在成员实际设备/网络验证代表性文件，逐步测试至实际需要的大小并确认最终启用上限。20 GiB、其他浏览器、真实物理断网、生产并发及成员网络均未由当前实验证明。

- XLSX 导入预览、TXT 待匹配、基本搜索、回收站、导出和备份。

### P1：试运行后按反馈补充

字幕只读差异对比、文件预览改进、术语资料入口、链接失效反馈、批量文件操作与容量看板。

### P2：有实际需求后单独评估

低清播放代理、字幕本地工具集成、网盘 API 连接器。审核、版本采用、切块管理、截止日期、讨论和交接记录不在后续规划中。

| 编号 | 场景 | 验收要求 |
|---|---|---|
| A01 | 从表格取文件 | 打开任务后直接下载最新版本或打开网盘，无需搜索群文件 |
| A02 | 同名新版本 | 给同一资源两次上传同名 ASS，两版字节都保留；第二版成功后立即显示为最新，无审核步骤 |

| A05 | 并发与幂等 | 两人同时上传保留不同版本；重复完成请求只生成一版；未完成上传不改变最新版 |
| A06 | 历史查看 | 倒序显示版本号、上传者、时间及文件信息，每个保留的 R2 旧版均能下载 |

## 15. 开发计划

按可验收的业务闭环分阶段交付。各阶段都包含前端、后端、数据和验证，不把全部前端或全部后端集中到单一阶段。阶段可按团队人力调整日历工期；退出条件未满足前不进入面向全组的正式试运行。

### 阶段 0：技术验证与项目骨架（已完成）

**工作内容：** 建立代码仓库和开发/测试环境，锁定 React、shadcn/ui 基础方案、TanStack Table、Uppy 及服务端 SDK 版本；完成前后端健康检查、数据库连接和最小 CI。用 Uppy 对接私有 R2，验证单次和分片上传、断网重试、取消、授权下载，以及目标浏览器/成员网络下 CORS 和续传表现。用少量真实任务做 TanStack Table 单元格编辑原型，验证姓名与状态合并显示及中文输入。

**结项日期与结果：** 2026-11-15 整理结项，阶段 0 标记为已完成。组件组合、中文分工编辑、私有 R2 直传/分片、服务端确认、签名下载与取消链路已有技术验证；具体证据及 Uppy 最近复测失败见第 13.3 节。此次结项确认选型可行并转交正式开发，不表示每次复测均成功或正式产品已通过验收。

**结项口径：** 不再以“成员网络全部覆盖、20 GiB 已实测”作为进入业务开发的前置条件；20 GiB 保留为待实测的候选配置，成员设备/网络与最终上限转入阶段 4/6 验收。新工程需重新初始化并验证实现，不继承原型的完成状态、数据库或 CI 成绩。

### 阶段 1：登录、项目与权限骨架

**工作内容：** 从全新正式工程开始，建立目录与配置、兼容依赖锁文件、开发/测试环境、数据库迁移、健康检查及可执行 CI；不沿用阶段 0 原型源码作为底座。实现成员登录/邀请、项目及成员关系、角色权限、私有 API 授权和基础导航。为所有任务与文件查询增加项目范围校验。

**退出条件：** 项目成员可以进入项目；非成员通过页面、API、任务 ID 或文件 ID 均无法访问该项目数据，也无法获得文件签名地址。

### 阶段 2：工作表与任务维护

**工作内容：** 实现分类工作表、可配置列、任务行、负责人、文字状态、自由分工说明和发布事实字段。使用 TanStack Table 实现显示、编辑、筛选、排序、固定标题列和列宽；使用 shadcn/ui 实现人员/状态选择、空状态和错误提示。处理保存反馈、重复请求及并发修改冲突。

**退出条件：** 统筹能建立一张工作表并增删任务；成员能按“我的/进行中”等条件查看任务并修改授权字段；刷新后数据保持一致；冲突不会静默覆盖对方修改。

### 阶段 3：任务文件区与网盘入口

**工作内容：** 建立 Artifact、ResourceLocation 等最小文件元数据模型，支持一个任务关联多个分类文件；允许一个资源登记多个网盘入口及提取码；实现文件侧栏、入口添加/编辑/删除、复制分享信息和外链跳转。此阶段先支持外链与待上传文件元数据。

**退出条件：** 从工作表打开任务后能看到对应资源；一个资源可以有多个独立网盘入口；入口变更不会修改其他入口，权限校验覆盖链接和提取码。

### 阶段 4：R2 上传、下载与版本历史

**工作内容：** 实现上传会话和额度预留、短时签名、Uppy 单次/分片上传、服务端完成校验、失败清理、授权下载。文件校验成功后创建不可覆盖的 ArtifactVersion 并更新资源 latest_version；保留提交者、时间、原文件名和大小；历史列表支持下载旧版。处理同名文件、并发上传、重复完成回调、取消和删除恢复。

**退出条件：** 两次上传同名文件会保留两份实际字节；第二版校验成功后立即显示为最新；未完成上传不改变最新版本；旧版可下载；无权限或伪造会话不能生成可用版本。

### 阶段 5：旧资料导入

**工作内容：** 实现 XLSX Sheet/字段映射、日期与文本预览、颜色状态人工映射、合并单元格确认和小批次导入；群文件树导入待匹配清单，供统筹关联任务和补文件链接。导入记录保留来源 Sheet、行号和批次，并支持幂等重跑。

**退出条件：** 用真实小样完成预览、确认、导入与重复导入；含糊的状态不被自动判断为完成；未取得实际文件的目录项清楚标记为待补资源。

### 阶段 6：运维与小范围试运行

**工作内容：** 完成工作表和文件清单导出、数据库及 R2 对象备份/恢复演练、回收站、上传孤儿清理、存储额度对账和最基本的运行监控。选一个活跃广播或长视频任务，让少量成员完成日常操作并记录问题。

**退出条件：** 从备份恢复试验项目后，任务、文件版本、网盘入口和下载关系完整；试运行成员能完成“看分工—取文件—传新版—查旧版”；确认初始额度与大文件上限适用于真实网络。
