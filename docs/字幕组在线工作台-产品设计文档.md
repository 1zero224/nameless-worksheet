## 1. 产品概述

### 1.1 要解决的问题

1. 工作内容全靠 QQ 群文件上传，杂乱，同一文件的多个版本混在一起。
2. 大文件传不了群文件，只能靠各种网盘。
3. 在工作表看完进度后，还要去群文件里翻对应文件。

### 1.2 产品结论

建设一个接近现有共享工作表的在线工作台：成员填写分工与进度，在具体任务上上传文件或填写一个/多个网盘链接。上传的文件保存到 Cloudflare R2，任务内直接展示最新版本，并可展开历史版本下载旧文件。

三条核心规则：

- **新版本保存成功即成为最新版本，旧版本文件保留。** 无审核，不另设“当前采用版本”。
- **长视频分工沿用表格方式。** P1、前半、00:00–13:00 等作为普通文本填写，按需手动增行；系统不切块、不校验时间区间。
- **沟通留在群里。** 不设截止日期，不提供讨论、评论和交接记录。

技术路线：组件自建的专用轻应用——正版 `shadcn/ui` 极简视觉体系 + `tw-animate-css` / `motion` / `sonner`（主界面与动效）+ 按 MIT 协议精简抽离的 Teable Canvas Grid（`apps/web/src/vendor/teable-grid/`，工作表主网格，见 [ADR-0005](adr/0005-teable-grid-and-unified-attachment-slots.md)）+ Uppy（上传）+ Cloudflare R2（存储）；后端为 Node.js + TypeScript + Fastify + PostgreSQL，单实例部署在 VPS 上（第 11.6 节）。

### 1.3 范围

| 类别 | 内容 |
|---|---|
| 首版包含 | 邀请加入与权限；首页任务流转看板与“我进行中的任务”；管理员的存储统计与清理页；分类工作表、可配置工序列、任务行、多负责人、手动状态、自由分工说明；多人实时协同（他人修改即时可见、在线成员与正在编辑的格子可见）；任务文件侧栏；R2 上传下载；多网盘链接；文件版本历史；基本搜索；XLSX 导入预览与群文件树待匹配清单；导出、回收站、备份 |
| 试运行后按反馈补充 | 字幕只读差异对比、文件预览改进、结构化术语库、链接失效反馈、批量文件操作 |
| 有实际需求再评估 | 低清播放代理、字幕本地工具集成、网盘 API 连接器 |
| **永久排除** | 版本审核与退回、当前采用版本与输入版本追踪、自动切块与分段校验、依赖与合稿管理、截止日期与逾期提醒、讨论评论与交接记录 |
| 首版不做 | 在线字幕编辑、网盘账号托管、自动跨盘搬运、公共外链、站外通知（邮件/QQ 推送）、同一格内多人同时打字的字符级合并、完整 Excel 式编辑（多格填充、复杂选区、公式）、财务与奖品管理 |

## 2. 现状依据

依据来自原工作簿 `无名字幕组任务分划.xlsx` 与群文件树导出 `group_file_tree_686700411.txt` 的只读分析。**这两个文件及提取结果当前不在本目录**，迁移开发前需重新取得。未访问群文件实际内容，未验证现存网盘链接；颜色、条件格式和合并单元格的视觉语义没有逐一复原。

### 2.1 工作簿（23 个工作表）

包含首页、歌曲翻译、BD评论音轨、长视频全熟、总集篇、切片熟肉、广播剧、中短视频、杂志、漫画、刺刺广播2025-2026、周报、直播与转播、⭐翻译对照表⭐、相关收益、赞助奖品清单、2025除夕抽奖奖项，以及六张留念表。解析时须通过 `xl/_rels/workbook.xml.rels` 对照 sheet ID 与文件路径，不能按 ZIP 枚举顺序配对表名。

| 观察 | 例子 | 设计影响 |
|---|---|---|
| 各类别工序不同 | 歌曲翻译有日文歌词/全曲翻译/校对/润色；杂志有嵌字/排版 | 工序列按工作表配置，提供列模板 |
| 长视频按时间段分工 | BD评论音轨为 0-6、6-12、12-18、18-24 | 自由分工说明 + 手动增行，不建分段对象 |
| 总集篇依赖跨文件参考 | 音源在群文件、动画字幕合集等 | 任务文件按原片/字幕/参考资料等分类挂载 |
| 多人协作与不适用 | 多人姓名、官中、不用翻、斜杠 | 多负责人；“不适用”状态；工序格可带简短备注 |
| 进度靠颜色表达 | 绿/黄/蓝与红字优先 | 状态与优先级结构化；导入时颜色人工映射 |
| 辅助内容混在工作簿 | 翻译对照表、收益、奖品 | 对照表进参考资料；财务与奖品留在原工具 |

行数只反映 XML 行节点，不等同任务数量；留念表不能全部认定为已发布。

### 2.2 群文件

目录导出报告 1,097 个文件、15.9 GiB（导出器统计，未复算，不含仅在网盘的资源）。同一目录下并存空轴、待校全篇、待校前13分钟、全场熟肉等文件；存在同名文件和多个 v2、（新）记录。没有哈希，不能确认同名文件是否相同，也不能把“前13分钟”自动归并为“全篇”的历史版本。文件类型覆盖 ASS、SRT、TXT、MP4、音频、PSD 等。

## 3. 角色与权限

邀请制，单字幕组使用；访客无法读取任何任务与资源。一个账号在项目内有一个角色。校对、终校是表格里的制作工序，不是系统角色。

角色只有两个：**管理员**与**普通用户**（用户已确认，v1.9 取消了原先的“统筹”角色，其权限并入管理员；管理员可以有多个，负责统筹的人直接设为管理员）。本文其余位置出现的“成员”泛指所有拥有账号的用户，不是一个角色。

| 操作 | 管理员 | 普通用户 |
|---|---|---|
| 查看工作表、文件、网盘入口与提取码 | ✓ | ✓ |
| 编辑任务行单元格、增加任务行 | ✓ | ✓ |
| 上传文件/新版本，增改网盘入口 | ✓ | ✓ |
| 删除任务、文件资源、历史版本（软删除，任务可在修改记录一键恢复） | ✓ | ✓ |
| 新建/编辑/删除工作表，配置列与看板列（见 [ADR-0003](adr/0003-open-worksheet-structure-to-all-users.md)） | ✓ | ✓ |
| 导入旧资料、导出 | ✓ | ✗ |
| 生成邀请、调整角色、重置他人密码 | ✓ | ✗ |
| 存储统计与清理、回收站清空、备份恢复 | ✓ | ✗ |

普通用户可编辑所有任务行而不限于自己负责的行，删除进回收站，延续共享表格的使用习惯（用户已确认）。登录方式为邀请链接注册 + 登录名密码；登录名与显示名分开，显示名即表格里的称呼（用户已确认）。系统拒绝降级最后一个管理员。**停用账号的功能暂不做**（用户已确认）：需要让某人无法再进入时，由管理员重置其密码且不把重置链接交给对方。所有权限在服务端校验；接口必须核验任务与文件所属项目，防止通过修改 ID 越权。

## 4. 信息架构与页面

### 4.1 导航

采用单行 44px 统一顶栏（取消左侧边栏），登录后默认进入首页：

- **左侧主导航轨**：项目名 \| **任务看板**（`/`） \| **通用文档**（`/docs`，阶段 3 新增） \| 各工作表标签页（可横向拖动排序，悬停 `⋯` 原地重命名/删除，全站不展示工作表标签色点） \| `+` 快速建表。
- **右侧操作区**：当前页面扩展操作（如工作表在线用户头像与「修改记录」抽屉入口）+ 右上角用户头像下拉菜单（工作表总览、个人设置、管理员另见用户与邀请 / 存储 / 实时通道诊断、退出登录）。
- **首页（`/`）**：左侧可折叠「我的任务」专注竖栏 + 右侧任务流转看板，见第 4.1.1 节。
- **通用文档（`/docs`）**：不挂在具体作品或任务上的项目级公共资源（如翻译对照表、通用字体包、字幕样式模板），全体已登录用户可协作维护，沿用同一套资源、版本与多入口机制（单层平铺，不设分类与分组）。结构化术语库留到试运行后。
- **无独立归档页与回收站页**：见 [ADR-0004](adr/0004-change-log-replaces-recycle-bin.md)，已完成靠工作表顶部「已发布」折叠区收起，误删靠工作表与通用文档各自的**修改记录**一键恢复。

### 4.1.1 首页：任务流转看板与左侧「我的任务」

首页由左侧可折叠「我的任务」竖栏与右侧任务流转看板组成，内容全部来自工作表，不需要另外维护；他人的修改实时反映在看板上。

**左侧「我的任务」专注竖栏**（桌面端冻结左侧可折叠，390px 窄屏收拢为顶部抽屉按钮）：按「进行中」「待开始」列出当前用户担任负责人的未发布工序条目，每条显示所属作品眉标（若有）、任务标题、工作表名与自己负责的工序，点击整卡打开详情侧栏，行内可直接一键「开始」「完成」或点资源按钮弹出快捷资源浮层。

**任务流转看板**：跨所有工作表，按工序分列，初始为四列（用户已确认）：**时轴 → 翻译 → 校对 → 嵌字**。不设“待发布”列；润色、排版、后期等其他工序暂不上看板。看板列采用自适应弹性宽度（1440px 屏幕可一屏完整展示 4 列），横向溢出时提供圆角滚动条与鼠标按住手拖滑动；列头支持一键竖向折叠为窄条。

**工序不写死**（用户要求）：

- 看板有哪些列、顺序如何，是项目级的配置，初始值为上述四列，所有已登录用户可按需增删、改名、调整顺序（[ADR-0003](adr/0003-open-worksheet-structure-to-all-users.md)），配置入口收拢在看板工具栏右侧「管理看板列」弹窗；程序里不出现固定的工序名称。
- 一个任务有哪些工序，完全由它所在工作表的工序列决定。工作表没有“校对”列，该表的任务就没有校对环节，永远不会出现在校对列，也不会显示空缺校对。
- 工作表里有该工序、但某个任务不需要时，把该格标为“不适用”，效果相同。
- 所有判断（卡片出现在哪列、何时离开看板、空缺认领）都只针对任务**实际拥有且适用**的工序。只有时轴和翻译两个工序的任务，两者都完成就离开看板。
- 当前没有任何卡片的列照常显示为空列，方便看出哪个环节没有积压。

- **全站统一状态色系与列内排序**：
  - 看板卡片、左侧「我的任务」与工作表工序格统一采用原工作表语义底色：**浅红 = 空缺（未开始且无负责人）**、**浅黄 = 进行中**、**纯白 = 已认领未开始**、**浅绿 = 已完成**、**浅灰 = 不适用**；
  - 看板每列与作品父容器内部均按 **空缺 → 进行中 → 已认领未开始** 稳定排序；
  - 状态行中的「空缺」直接融合为带举手图标的可点击认领按钮（点击原子抢认领，仅填负责人并保持未开始）；其余未轮到的空缺工序在开启「仅看空缺」时展开为可点击认领按钮。
- **独立任务与作品父子展示**：
  - 无所属作品的独立任务（或同列仅 1 条的归属作品任务）采用极简两层状态底色卡片（点击整卡打开任务详情侧栏，状态行右侧提供快捷资源弹层按钮 `TaskResourcesPopover`）；
  - 同一看板列内归属同一「作品」的 `≥2` 条任务自动聚合在中性白底「作品父容器」内默认展开，以圆角树形引导线（`├─ / └─`）展示各分段子卡并支持跨列悬停联动高亮，每条分段均可直接举手认领、打开快捷资源浮层或点开详情侧栏。
- **卡片出现在哪些列**：一个任务可以同时出现在多列（用户已确认）。满足以下任一条件，任务就出现在该工序的列里：
  - 该工序状态为“进行中”——时轴和翻译并行时，两列都显示这个任务“进行中”；
  - 该工序是这个任务上看板的工序中第一个尚未完成的适用工序——保证还没人动的任务也有地方显示、可以被认领。
- **流转**：工序标为已完成后，卡片从该列消失，并出现在下一个未完成工序的列。任务拥有的上看板工序全部完成（或不适用）后，离开看板。位置由工序状态自动推导，不能手动拖动。
- “适用工序”指状态不是“不适用”的工序——例如标了“官中、不用翻”的任务不会出现在翻译列。
- 工作表的每个工序列在配置中指定对应哪个看板列，或者不上看板；新建时按名称自动匹配，所有用户可按需调整（[ADR-0003](adr/0003-open-worksheet-structure-to-all-users.md)）。

看板工具栏：融合关键词跨表检索框、按工作表筛选、按作品筛选、「仅看空缺」、「仅看与我有关」、「管理看板列」。

### 4.2 工作表

采用 Teable / 飞书多维表格风格的全屏贴边高密度画布（由抽离去耦的 MIT `teable-grid` 驱动）；看板统一由顶栏「任务看板」标签承载，工作表内不再设冗余的「表格视图 / 看板视图」切换。一行表示一项任务或手工填写的分工，标题列与行号列冻结，「分工说明」列位于最末，彻底移除冗余的「作品」列（作品归属由作品大标题横幅与任务详情侧栏统一承担）。

- **作品大标题横幅与无作品平铺**（[ADR-0005](adr/0005-teable-grid-and-unified-attachment-slots.md)）：
  - 归属同一「作品」的任务自动聚合在一条**跨整行可折叠的「作品大标题横幅」**下方，作品名与完成进度右侧**靠左紧跟**整片共用资源快捷胶囊、`+ 附件`、`+ 添加分段`、重命名与解散分组（去掉任务行左侧彩色导轨强调线），还原原工作簿的大标题分段直觉；
  - 只要作品下有未删任务 **或** 挂有未删作品共用资源，横幅即保持可见；解散分组时若作品下仍有共用资源，弹窗提示并默认保留横幅与共用资源（可选勾选同时软删）；
  - 无所属作品的独立任务直接平铺，不套横幅。
- **工序格（单格走完一道工序）**：以**整格柔和状态底色**直观反映进度（空缺浅红、进行中浅黄、已认领未开始纯白、已完成浅绿、不适用浅灰），格内左侧显示负责人并紧邻其右侧**直接展示工序备注**，右侧为**最新资源角标热区**（点击角标弹出靠左对齐的轻量快速取用浮层，2 次点击内即可打开网盘、复制提取码、分享或更新版本）；点击格子其他区域弹出轻量浮层修改负责人（可多选或填纯文本）、状态、备注及管理本工序资源。
- **单元格右键菜单**：右键任意单元格可直接「展开任务详情」「查看单元格修改记录」（按当前单元格字段/工序/资源精准过滤，顶部支持一键切换「当前单元格 / 整条任务」）「在下方插入一行」「删除任务」。
- **固定「文件」列**：显示本任务汇总资源总数（含任务级与各工序格），点击直达任务详情侧栏文件区，可在字段显隐中按需隐藏。
- **表头原地交互**：表头最右侧 `+` 原地新增列，点击列头原地改名、调序、配置看板列映射、隐藏或删除；保留列宽拖拽与键盘跨格导航。
- **标题、分工说明**双击或回车进入 DOM 浮层直接编辑，完整保护中文输入法组字；保存失败时保留输入并提示重试。
- **已发布折叠区**：已发布任务默认收起在工作表顶部紧凑折叠条中，展开后可查阅或编辑；所有工序完成但未发布的任务不折叠。
- **行顺序**由用户手动维护，紧贴最新行提供原地新建行，支持原地插入、同作品内及跨作品拖动调整。
- **实时协同**：他人的修改无需刷新即出现在表格中；顶栏右侧槽显示当前在线用户与「修改记录」按钮，他人选中或正在编辑的格子通过 Canvas `collaborators` 以彩色边框与名字浮标标出（规则见第 6.3 节）。
- **快捷筛选**：全部、我的、未开始、进行中、全工序已完成；另可按作品、负责人筛选、本地排序以及通过融合关键词搜索框实现本表筛选与跨表检索。
- 发布日作为已发生事实保留；不设计划完成日、截止日或逾期状态。

### 4.3 统一四级资源挂载与详情侧栏

阶段 3 起，资源挂载覆盖四个清晰层级（均共用同一套版本历史与多入口机制；**全站不设全局「资源分类」或「分组」下拉**，由挂载位置、本表工序列与资源名自然表达语义）：

1. **作品大标题级（整片共用资源）**：原片、纯音源、通用字体包、总合稿/压制成品直接挂在「作品大标题横幅」上，紧跟标题与进度展示快捷胶囊（无提取码的单链接直接新标签打开，其余共用单 `Popover` 动态锚点弹出轻量快速取用浮层，连续切换不闪退）；打开该作品下任意一条分段任务的详情侧栏时，在**侧栏最底部**展示「所属作品共用资源」平铺列表，避免干扰上方核心字段与本任务交付。
2. **任务行级**：无作品大标题的独立任务（如广播、切片）的原片、封面、成品或不属于单一工序的杂项挂在任务行上，通过「文件」列与任务详情侧栏「任务其他资源」访问。
3. **工序格级**：某道具体工序产出的交付物（如空轴、翻译稿、校对稿、嵌字成品）直接挂在对应工序格上，新建时顶部以亮色层级标签展示「工作表 › 作品 › 任务 › 工序」，资源名默认预填 **「作品名-任务名-工序」**（无作品时省略作品名）；格内角标点击弹出靠左对齐的轻量快速取用浮层；在任务详情侧栏中与工序分工合并为统一的 **「工序与交付」** 双段式卡片（上半部白底编辑负责人 `Popover` / 状态 / 带图标标签的备注，下半部微灰托盘直接展示本工序交付资源）。
4. **通用文档（`/docs`，项目级）**：翻译对照表、通用字幕样式模板、公共字体包等不归属具体作品/任务的少数公共资源放在顶栏「通用文档」页（单层平铺列表 + 关键词过滤 + 修改记录抽屉）。

```text
长视频全熟 / 作品大标题：5th-BD 花絮 [已完成 0/2] [🔗 原片] [🔑 字体包] [+ 附件] [+ 添加分段] ···
  └─ 任务：P1 00:00–13:00
     校对格：小林 · 先核时间轴  [🔗 v3]  ← 点击弹出靠左对齐的轻量取用浮层
     [详情侧栏：基础字段 | 工序与交付（上白分工 + 下灰交付） | 任务其他资源 | 修改记录 | 作品共用资源]
```

- **紧凑平铺资源与树形引导**：资源卡片/列表采用去嵌套平铺排布，资源标题旁内嵌版本更新胶囊（`v1` + `+`，悬浮/聚焦展开「更新」），仅当存在多个版本时展示历史展开按钮；资源与下方网盘链接通过左侧 2px 树形竖线标明从属关系；网盘单行交互为 **「网盘名直接作为外链」+「提取码胶囊直接点击复制」+ 紧邻「分享」按钮**，右侧网盘 `···` 悬浮显现；低频「多网盘」功能收纳在资源 `···` 菜单中（界面文案统一使用「多网盘」，0 链接时显示「待补充多网盘」）。
- **版本历史**按版本号倒序列出，任意保留的旧版均可取用/下载。
- **精简表单与单窗口聚焦**：新建与更新弹窗仅保留分享文本解析、链接、网盘服务商、提取码与单个可选「备注」（移除链接指向类型、有效期至与单独的 v1 版本说明）；从资源浮层弹出新建/更新/多网盘弹窗时自动关闭背后浮层，保持单窗口聚焦。阶段 4 上传文件时同样显式选择新建资源或上传新版本，不得仅凭同名自动合并。
- **删除与降级保护**：删除工序列时，关联该工序列的工序资源自动降级为任务级资源并保留原名、记入修改记录；解散含共用资源的作品分组时须弹出明确确认且默认保留横幅与共用资源。
- **改名与移动归属**：资源支持改名及在项目内移动归属层级（通用文档 / 作品 / 任务 / 工序格），这些元数据操作均不产生新版本。

### 4.4 融合资源检索

不再保留独立的 `/search` 全页路由，统一由首页与工作表筛选栏的融合搜索框（`KeywordSearchInput`）即时下拉完成跨表检索。搜索范围：任务标题、所属作品、分工说明、负责人显示名/纯文本名字、工序备注、自定义文本列、**资源名称**（阶段 4 含原文件名）与**通用文档名称**；结果列出所在工作表与任务（并标出命中资源名），另有「通用文档」分区，点击直达对应任务详情或 `/docs` 并定位高亮。**提取码与网盘 URL 严禁进入搜索索引。**不做文件内容全文检索。

### 4.5 设备与浏览器

同一套网页同时服务桌面和手机，功能不做区分，手机上同样可以编辑和上传（用户已确认）。差别只在布局：手机上侧栏改为全屏详情，看板各列改为可左右滑动，宽表横向滚动。需要知道的一点：手机浏览器切到后台或锁屏后可能暂停上传，回到页面后按断点续传继续，因此很大的文件在手机上不保证一次传完。支持当前主流桌面与手机浏览器的近期版本，界面仅简体中文，时间按浏览器本地时区显示。

## 5. 数据模型

| 对象 | 关键字段 | 说明 |
|---|---|---|
| User | 显示名、别名列表、登录凭据、状态 | 别名用于匹配旧表中的称呼 |
| Project / Membership | 项目；用户、角色（管理员/普通用户） | 项目是权限边界，首版只有一个，由初始化命令创建，不提供新建或切换项目的界面 |
| Invite | 令牌、预设角色、过期时间、可用次数 | 邀请链接 |
| Worksheet | 名称、分类、排序、归档时间 | 对应原表的一个 Sheet |
| BoardColumn | 所属项目、名称、排序 | 看板的列；初始为时轴、翻译、校对、嵌字，可增删改 |
| ColumnConfig | 名称、类型、排序、宽度、是否隐藏、对应的 BoardColumn（仅工序列，可空） | 类型：文本 / 工序 / 日期 / 链接 / 文件；BoardColumn 为空表示该工序不上看板 |
| Work | 所属工作表、作品名称（同表内唯一） | 作品大标题；在工作表中作为跨整行折叠分组头，在看板中作为聚合卡；阶段 3 起支持直接挂载作品级共用附件 |
| Task | 标题、所属作品（Work 引用，可空）、分工说明、优先级、发布状态/发布日/发布链接、自定义文本列值、排序键、revision、导入来源、删除时间 | |
| StageCell | 任务 × 工序列；负责人列表、状态、备注 | 负责人可为项目用户或纯文本名字 |
| Artifact | 所属工作表（冗余可空）、所属作品（可空）、所属任务（可空）、所属工序列（可空）、名称、`latest_version_id`、删除时间 | 统一四级逻辑资源（无全局分类/分组，由数据库 `CHECK` 约束合法组合）：全空=通用文档；`work_id`=作品共用资源；`task_id` 无 `stage_column_id`=任务级资源；`task_id + stage_column_id`=工序格交付资源 |
| ArtifactVersion | 版本号、登记/上传者、时间、可选说明、原文件名（阶段 4 可空）、大小（阶段 4 可空）、MIME（阶段 4 可空）、Blob 引用（阶段 4 可空）、删除时间 | 不可覆盖，版本号由数据库行锁递增分配 |
| Blob | R2 key、大小、内容类型、可选 SHA-256 | 实际字节（阶段 4） |
| UploadSession | 目标资源、R2 key、uploadId、文件指纹、大小、状态、过期时间、幂等键 | 分片状态以 R2 ListParts 为准（阶段 4） |
| ResourceLocation | 所属版本、类型（`cloud_link` / `r2`）、服务商、URL、提取码、文件或文件夹、可选到期日、备注、删除时间 | 一个版本可有多个入口；允许版本暂时为 0 入口（待补充入口）；不设验证/可用状态字段 |
| ImportBatch | 源文件、Sheet、操作者、时间 | 任务行记录批次与原行号 |
| RealtimeEvent | 递增编号、订阅范围（工作表/任务）、事件类型、载荷、发起连接 ID、时间 | 仅用于重连补发，短期保留后清理；不是活动记录 |

**不建立** Segment、Review、Adoption、Comment、交接事件或输入版本绑定实体。

关键约定：

- **负责人与账号**：旧表里的姓名很多对应不到账号（历史成员、外援、“官中”）。负责人字段同时接受成员账号和纯文本名字；纯文本名字可在成员加入后通过别名批量关联到账号。“我的任务”只统计已关联账号的条目。
- **版本号**在同一资源内递增，由数据库分配；`latest_version_id` 仅表示最新保存成功的版本，不含审核或采用含义。
- **入口挂在版本上**。给已有版本增改入口不产生新版本；文件内容变了才建新版本。新版本可以是上传到 R2 的文件，也可以只登记网盘链接（建议默认）。
- **镜像与合集**：同一版本的多个入口应指向相同内容，无法确认时在备注说明，不声称哈希一致。网盘文件夹可作为资料合集入口，其内容由网盘维护。**只登记链接无法保留网盘端被删除或覆盖的字节**，需要保证可下载的历史文件应上传到 R2。

## 6. 业务规则

### 6.1 使用流程

1. 管理员新建分类工作表，从列模板选择或自行配置工序列。
2. 所有用户填写负责人与进度；长视频需要几行就增加几行。
3. 打开任务文件侧栏，下载最新文件或打开网盘；需要旧文件时展开版本历史。
4. 上传新资源或新版本，保存成功后立即成为最新。
5. 为资源补充网盘入口与提取码。
6. 成员自行更新工序状态；发布后手工填写发布状态与链接。

### 6.2 状态

- 工序状态：未开始、进行中、已完成、不适用。“不适用”不计入未完成。
- 发布状态：未发布、已发布，单独手工维护。
- 文件上传与工序状态互不联动。系统不跟踪谁下载了哪版，不提示上游版本变化，不要求发布绑定文件版本，不检查各段是否齐全。

### 6.3 实时协同

用户已确认：做实时协同，采用“服务端权威 + 事件广播”方式，不做字符级合并。技术实现见第 11.5 节。

- **即时可见**：任一成员对任务行、工序格、行顺序、列配置、文件资源、版本、网盘入口的修改，在其他打开同一工作表或同一任务侧栏的成员界面上即时更新，目标延迟 1 秒内。
- **在线状态**：显示当前打开此工作表的成员；显示每人选中的格子，以及是否正在编辑。在线状态是临时信息，不落库，不形成活动记录。
- **编辑即保存**：按字段提交修改。两人改同一行的不同字段，两者都保留。
- **同一格冲突**：因为能看到对方正在编辑，冲突应当少见。若仍发生——自己正在编辑的格子收到了他人的新值——不覆盖正在输入的内容，在格子旁提示“某某刚把此格改为…”，由用户选择保留自己的输入或采用对方的值。未在编辑的格子直接显示最新值。
- **不做字符级合并**：同一个文本格内不支持两人同时打字并合并（单元格内容都是短文本、人员和状态，没有必要）。
- **断线**：界面显示“连接中断，正在重连”。断线期间的修改仍通过普通请求提交，失败则保留输入并提示。重连后自动补齐错过的变更，补不齐时整表重新拉取。
- **上传**：他人的上传进度不广播，只在新版本保存成功后通知。
- 两人同时给同一资源上传，各自成为一个新版本，互不覆盖；重复的完成请求只生成一个版本；上传中或校验失败的文件不改变最新版本。

### 6.4 删除、修改记录恢复与物理清理

- 延续 [ADR-0004](adr/0004-change-log-replaces-recycle-bin.md)，**不建独立回收站页面**。任务、资源、版本与入口的删除均采用软删除（`deleted_at`），删除后弹出带「撤销」的 Toast，并在工作表或通用文档的**修改记录**抽屉中支持一键恢复。
- 删除任务时，其名下资源随任务隐藏（不覆盖单条资源的自身删除标记），恢复任务时版本与入口关系精确还原。
- 旧版本默认永久保留。删除最新版前须明确二次确认，删除后自动把仍保留的最高版本号显示为最新。
- 物理清理 R2 对象留待阶段 6 管理员存储管理页手动执行，清理前检查是否仍被其他版本引用。

## 7. 网盘链接

“支持各种网盘”在首版的含义是：登记任意合法的 HTTP/HTTPS 分享地址，展示并跳转。不承诺统一登录、直链下载、在线播放或自动检测有效性，也不维护人工“可用/失效”验证状态（失效直接删掉换新或在备注说明）。

- 自动识别百度、阿里、夸克、天翼、115、Google Drive、MEGA、OneDrive；未知域名归为“其他”，识别失败不拒绝。只接受 `http://` 与 `https://` 协议。
- 支持一步表单粘贴带提取码的整段分享文本，自动解析服务商、URL 与提取码后由用户确认；表单精简为资源名、链接、网盘服务商、提取码与单个可选备注（低频多网盘操作收纳在资源 `···` 菜单中，界面统称「多网盘」）。
- 网盘行采用单行紧凑交互：点击网盘名直接新标签打开外链，点击提取码胶囊直接复制并即时反馈，紧邻右侧放置「分享」一键复制完整分享信息按钮。
- 服务器绝不抓取用户提交的 URL。
- 提取码与链接受同一项目访问权限控制，严禁写入服务端日志、实时事件载荷、修改记录与搜索索引。

## 8. R2 存储与上传下载

### 8.1 上传流程

采用私有 bucket，浏览器直传，业务服务只处理元数据，不中转文件字节。

```text
申请上传会话（后端校验权限、目标任务、大小不超过单文件上限，生成随机不可复用的对象 key）
  → 小文件：签名单次 PUT；大文件：分片逐片签名上传
  → 请求完成：服务端按会话绑定的 key 用 ListParts 核对并合并，HEAD 校验大小
  → 幂等地创建 ArtifactVersion、更新 latest_version
```

实现要求：

1. 后端持有密钥，只签发短期能力。服务端不信任客户端传回的 key、大小、ETag 或任务 ID，一律以会话记录为准。
2. 界面区分“上传中、校验中、已保存、失败、已取消”；传输 100% 不等于已保存。
3. ETag 不是文件内容哈希，不能当作 SHA-256 使用。
4. CORS 只允许产品域名与所需的 GET/HEAD/PUT 及请求头，并暴露 ETag。CORS 不是鉴权手段。
5. 预签名 URL 使用 S3 API 域名，不能当作自定义域名的永久链接。
6. 最终对象不可覆盖：每次上传使用新 key。

初始参数（集中配置，按成员网络调整）：

| 参数 | 初始值 | 说明 |
|---|---|---|
| 分片阈值 | 100 MiB | 超过即分片 |
| 分片大小 / 并发 | 20 MiB / 3 | 阶段 0 实验用值 |
| 上传签名有效期 | 10 分钟 | |
| 下载签名有效期 | 10 分钟 | |
| 单文件上限 | 10 GiB（用户已确认） | **该大小未实测**，阶段 4/6 在成员网络下验证；超过的文件走网盘入口 |
| 回收站保留 | 30 天 | |

R2 官方限制（研究日期 2026-11-08）：单对象上限 5 TiB、单次 PUT 上限 5 GiB、最多 10,000 分片；Limits 页面对 multipart 另给出 4.995 TiB。理论上限不是产品承诺。

### 8.2 断点续传与取消

- 短暂断网只重传失败分片。
- 刷新页面后可恢复，但需用户重新选择同一个本地文件；校验文件指纹后用 ListParts 复用已完成分片。指纹用分块 SHA-256 计算，避免整文件入内存；**指纹阶段必须显示进度、可取消、有超时提示**（阶段 0 最近一次复测卡在此处）。大小相同但内容不同的文件不得误恢复。
- 不承诺浏览器关闭后后台续传。
- 取消以服务端 abort 成功为准；abort 失败要提示。
- 已取消、已保存或已过期的会话不能让重传永久失败：清理本地失效记录并提示重新开始。
- 后台任务定时清理过期会话的未完成分片和无数据库引用的孤立对象，设宽限期避免误删。

### 8.3 下载

业务 API 鉴权后签发短期 GET 地址。对象 key 是随机值，下载时须通过 Content-Disposition 还原原始文件名（含中文文件名的正确编码），并强制以附件方式下载，危险类型不在站点同源打开。撤权后停止签发新链接，已签发的链接在过期前仍可能有效。

### 8.4 预览

| 类型 | 首版处理 |
|---|---|
| ASS / SRT / TXT | 安全转义的只读文本；编码检测失败时让用户选择编码，不改原字节。ASS 文本预览不等于特效渲染 |
| 图片 | 浏览器可解码的格式直接显示 |
| 音视频 | 浏览器支持的编码直接播放，否则提供下载/网盘入口 |
| PSD、字体、压缩包等 | 只显示元数据与下载 |

### 8.5 存储统计与清理（管理员）

不设项目总额度和成员额度（用户已确认），上传只受单文件上限约束。历史版本默认全部保留（用户已确认），空间由管理员在本页手动管理。

**统计**：总占用与按 R2 标价估算的月费用；按工作表、任务、文件分类、上传者的占用分布；其中“非最新版本”“回收站中”“未完成上传”各占多少；近期增长趋势。

**浏览**：文件版本列表，显示所属任务、资源名、版本号、是否最新、大小、上传者、时间，可按大小和时间排序。

**快捷选择**：一键筛出并全选以下几类，可叠加条件，实时显示选中项可释放的空间。

- 非最新的历史版本
- 已发布任务的历史版本
- 超过指定天数的历史版本
- 大于指定大小的文件
- 回收站中的内容
- 未完成的上传与无引用的孤立对象

**清理**：选中项可“移入回收站”（30 天内可恢复）或“立即永久删除”。永久删除前列出数量与总大小并要求二次确认。不能通过快捷选择删除某个资源的最新版本——那需要到任务里显式操作。被其他版本共用的字节不会被物理删除。

清理是管理员的手动操作，系统不自动删除任何历史版本。

## 9. 安全、保留与备份

- **实时通道**：握手时校验登录会话与来源；每次订阅校验项目权限；会话失效（登出、密码被重置或修改）时连接立即断开；广播事件不含提取码。
- **账号**：密码只存加盐哈希；登录与邀请接口限速；邀请链接有过期时间和次数上限（默认 7 天、单次，可配置，可作废）；管理员可为他人生成一次性密码重置链接（24 小时有效，管理员看不到密码）。登录保持 30 天滑动续期，允许多设备；改密码后其他设备被登出。密码至少 8 位，不能与登录名相同。会话 Cookie 设 HttpOnly/Secure/SameSite，写操作防 CSRF。停用账号暂不做。
- **内容安全**：所有用户输入与文本预览输出时转义；外链只允许 http/https，新窗口打开并隔离来源页。
- **日志**：安全与故障日志仅供运维，不包含提取码，不演变为成员需要填写的业务记录。不建设面向成员的活动流。
- **备份**：数据库每日备份到独立的 R2 bucket，并定期演练恢复。文件备份的含义：R2 自身不会无故丢数据，但程序缺陷、清理误操作或账号出问题时，被删的文件无法找回，另存一份就是为了这种情况；代价是存储费用翻倍。因此默认只给字幕、文本等小文件另存一份——它们是组里的劳动成果、体积很小；大视频不另存（建议默认，见第 14.1 节）。
- **导出**：导出工作表、文件版本与入口的关联清单；提取码仅对有导出权限的角色包含。

## 10. 迁移

1. 保留原始 XLSX/TXT 的只读备份；每条导入记录保留源文件、Sheet、行范围与批次 ID。
2. 按实际 sheet 关系解析，逐表选择标题行与字段映射，先预览再确认。首页、财务、奖品表不导入为任务；翻译对照表进参考资料。
3. 合并单元格只对已确认的父级字段向下继承；工序姓名和状态的空白不自动填充。
4. Excel 日期序列、时间分数、文本时间分别转换并保留原值；不从 0.46875 这类值猜测是日期还是时长。
5. 每张表人工确认颜色与状态的映射，区分“完成未发布”“已发布”“部分完成”“优先级”。存疑记录进人工确认列表；**不能因为格子里有姓名就判为完成**。
6. 姓名先作为纯文本负责人导入，再通过成员别名批量关联账号（见第 5 节）。
7. 群文件树导入为“待匹配资源清单”：目录、关键词和集数只提供匹配建议，由用户确认归属。同名文件保留为不同条目。TXT 只有目录线索，成员实际上传文件或补网盘链接后才形成可访问入口，此前显示“待补资源”。
8. 先选一个进行中的长视频或广播任务试运行；旧表同期只读核对，避免长期双写。确认后分批迁移活跃任务，留念表按归档处理。

### 11.3 阶段 0 结论

**技术路线可行。** 已验证：工序单元格的合并显示与中文编辑、revision 冲突检测、浏览器直传私有 R2 与 CORS、签名下载、128 MiB 分片的恢复/完成/取消链路。

未验证、须在后续阶段覆盖：实时通道（WebSocket 广播、重连补发、在线状态，阶段 0 完全没有涉及）、成员真实设备与网络、其他浏览器、真实物理断网、10 GiB 上限（阶段 0 最大只传过 1 GiB）、生产并发、成员/项目鉴权。**最近一次 Uppy 浏览器复测（2026-11-15，128 MiB）失败**，卡在文件指纹检查后超时，原因未定位；新实现必须覆盖该场景。证据明细见附录 B。

原型没有鉴权、版本保留与清理等保障，不可公开部署，其数据库不是正式业务数据。

### 11.5 实时通道

#### 方案选择

五个带协作能力的参考项目里有三种做法（源码位置见附录 A）：

| 做法 | 代表 | 原理 | 对本项目 |
|---|---|---|---|
| **服务端权威 + 事件广播** | Baserow | 写入仍走普通 API；事务提交后把变更事件广播给订阅了该表的连接；事件带递增编号并留存一段时间，重连时按游标补发；在线状态单独走临时通道 | **采用** |
| 操作变换（OT） | Teable（ShareDB + json0） | 每条记录是一个带版本的文档，变更表示为操作；同样在事务提交后经 Redis 发布 | 模型更重，强依赖 Redis；它解决的任意并发合并本项目用不上 |
| CRDT | Plane（Yjs + Hocuspocus，仅用于页面富文本） | 文档状态在客户端合并，服务端定期落库 | 适合长文本共同编辑；会让关系数据库不再是唯一事实来源，权限、搜索、导入都变复杂 |

NocoDB 社区版的 socket 网关只承载遥测，Vikunja 没有实时通道，二者不作参考。

选择理由：单元格都是短文本、人员列表和状态，字段级“后写生效 + 可见的编辑状态”已足够；权限、搜索、导入、版本事务都依赖关系数据库作为唯一事实来源，事件广播不改变这一点。若将来确实需要在长文本里共同编辑，可对单个字段引入 Yjs，而不必推翻整体方案。

#### 设计要点

1. **单一写入路径**：所有修改走业务 API，由它校验权限与数据。WebSocket 只用于服务端推送和在线状态上报，客户端不通过它写业务数据。
2. **提交后广播**：事件在数据库事务提交之后发出，避免广播了随后回滚的变更（Baserow 用 `transaction.on_commit`，Teable 用 `bindAfterTransaction`）。
3. **订阅范围**：连接握手时用登录会话鉴权；按“工作表”和“任务”订阅，订阅时校验项目权限；会话失效时服务端主动断开其连接。
4. **事件内容**：单元格变更携带行 ID、变更字段、新值、行 revision 和操作者；文件、版本、网盘入口的变更只携带对象 ID，由客户端按自己的权限重新读取——这样提取码不经过广播通道。
5. **发起者去重**：每个连接有自己的 ID，请求时带上，服务端广播时跳过该连接；发起者以接口返回值为准。
6. **重连补发**：事件写入事件表，编号单调递增，保留 24 小时（用户委托决定：足以覆盖电脑合盖过夜后第二天继续的情况，而小组一天的事件量很小）；单次补发上限 500 条。客户端记住最后收到的编号，重连时提交；服务端补发其后的事件。游标缺失、过期或积压超过上限时，回复“请整表刷新”（与 Baserow 的 `replay_events` 行为一致）。
7. **在线状态**：客户端上报当前焦点 `{行, 列, 是否在编辑}`，服务端转发给同一工作表的其他连接；连接断开即清除。只存内存，不落库。
8. **客户端状态**：收到事件后按行 revision 合并进本地缓存；revision 不连续说明漏了事件，触发该行或整表重新读取。乐观更新失败时回滚并提示。
9. **部署**：首版单实例，事件在进程内分发，不引入 Redis（三个参考项目用 Redis 是为了多实例）。把分发层做成可替换的接口，将来需要多实例时再接入发布订阅。
10. **降级**：实时通道不可用时，产品仍可用——编辑、上传、下载都不依赖它，只是看不到他人的即时变更，重连后补齐。

### 11.6 后端、数据库与部署（已确定）

用户委托选型，并说明 VPS 与 Cloudflare 均可。结论：**应用与数据库跑在一台 VPS 上，文件放 R2，Cloudflare 只做 DNS 与可选的反向代理。**

| 层次 | 选择 | 理由 |
|---|---|---|
| 语言 | TypeScript，前后端同一语言 | 接口类型与校验规则前后端共用，实时事件的结构只定义一次 |
| 运行时与框架 | Node.js（当前 LTS）+ Fastify | 阶段 0 已用 Fastify 跑通签名、分片与完成校验链路；原生支持长连接 |
| 实时通道 | Fastify 的 WebSocket 插件（基于 `ws`） | 与业务 API 同进程，提交后直接进程内广播 |
| 数据库 | PostgreSQL | 版本号分配、幂等提交都需要可靠的事务与行锁；支持中文子串搜索所需的索引 |
| 数据访问与迁移 | Drizzle ORM 及其迁移工具 | 类型安全，生成的 SQL 透明，便于审查事务 |
| 后台作业 | 基于 PostgreSQL 的任务队列（如 pg-boss） | 过期上传清理、占用统计、备份都能做，不需要另装 Redis |
| 登录 | 邀请链接注册 + 用户名密码；Argon2id 哈希；会话存数据库，Cookie 承载 | 用户已确认登录方式 |
| 输入校验 | Zod，前后端共用同一份定义 | |
| 前端构建 | Vite 构建的单页应用，由同一服务托管静态文件 | 登录后才可用，不需要服务端渲染 |
| 测试 | Vitest（单元与接口）+ Playwright（浏览器流程，含双浏览器协同场景） | |
| 部署 | Docker Compose：应用、PostgreSQL；HTTPS 与反向代理由 Caddy 承担 | 单实例。当前 VPS 与其他服务共用，80/443 已由机器上现有的 Caddy 容器占用，因此复用它（加一个站点块），Compose 里自带的 Caddy 只作为换到干净机器时的可选项。见下文“当前部署环境” |
| 备份 | 每日 `pg_dump` 加密后传到独立的 R2 bucket；文件 bucket 另做副本 | |

**为什么不放在 Cloudflare Workers 上**：可行，但每一项都要换成平台专有的做法——长连接要用 Durable Objects，数据库要用 D1（SQLite 语义，事务能力受限）或外接数据库，后台作业要用 Cron Triggers 与 Queues，本地开发和测试也要模拟这些组件。对一个小组自用的工具，一台 VPS 上的单进程更简单，出问题也更容易排查。R2 用的是 S3 兼容接口，从 VPS 访问没有障碍。

**为什么不用 SQLite**：单机够用，但并发上传时的版本号分配要靠行级锁，PostgreSQL 更稳妥，备份恢复工具也更成熟。

VPS 起步规格 2 核 / 2–4 GB 内存即可（文件字节不经过服务器），实际按试运行调整。具体依赖版本在阶段 1 锁定。

**当前部署环境**（2026-11-15 只读核实）：香港 VPS，Ubuntu 22.04，4 核 / 3.8 GB 内存（与其他服务共用，可用约 1.8 GB），已装 Docker 与 Compose。系统盘只剩约 6.5 GB，部署目录与数据库数据放在挂载盘 `/srv/storage`（60 GB，剩约 30 GB）。域名尚未购买，暂用 `worksheet.45.207.215.102.sslip.io`（与机器上其他站点同一写法），买到域名后改一个配置项切换。镜像由 GitHub Actions 构建并推到 GHCR，VPS 只拉取运行，不在机器上构建。代码托管在 GitHub 私有仓库 `1zero224/nameless-worksheet`。

阶段间依次依赖。可并行的部分：数据契约确定后，前端页面与后端 API 并行；阶段 2 任务接口稳定后，文件界面与文件元数据 API 并行；上传 UI 与签名/会话 API 并行，但版本历史须等完成校验与版本事务接口确定后接入；旧资料清洗可提前做，生产导入须等数据模型稳定。

首个里程碑：**登录 → 打开工作表 → 改负责人或状态 → 打开任务文件 → 上传到 R2 → 看到新版本 → 下载旧版本。**
