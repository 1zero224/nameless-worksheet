## 1. 目标与退出条件

阶段 2 在阶段 1 的登录、权限与实时通道骨架之上，交付完整的表格协作与首页任务流转闭环：用户可建表、配列、填分工与进度、查看首页看板与“我的任务”、跨表检索任务、查看修改记录并恢复误删任务，且多人同时编辑实时同步、焦点可见、冲突不丢字。

退出条件（全部满足才算完成，逐条对应第 10 节的验收清单）：

1. **建表与结构配置（A28）**：所有已登录用户均可新建/改名/排序/删除工作表，按模板或自定义增删改工序列与自定义列（文本/日期/链接），调整列宽与列显隐，并配置项目级看板列；删除工作表与列需二次确认。
2. **任务与分工填写（A08）**：可增删任务、在任意位置插入与拖动排序、手填自由分工说明、选择或新建作品、设置优先级与发布信息；负责人同时支持选择项目用户与自由输入纯文本名字。
3. **已发布折叠与修改记录**：已发布任务默认收起在工作表顶部的“已发布”折叠区（所有工序完成但未发布的不折叠）；工作表与任务详情侧栏可查看字段级修改记录，且任意用户可从删除记录一键恢复被删任务。
4. **首页看板、认领与我的任务（A22、A23、A24、A25、A28）**：看板初始为时轴/翻译/校对/嵌字四列；并行进行中的任务多列同时显示，未开始任务落在第一个未完成上看板适用工序列，已发布或上看板适用工序全完成后离开看板；工作表没有的工序不参与判断；类型标签、作品标签（点击筛选）与缺人标签（含不上看板工序）正确；点击缺人标签认领只填负责人、保持未开始，并发抢认领时后到者提示失败；顶部“我进行中的任务”与 `/my-tasks` 准确展示并可快捷改状态。
5. **检索与详情侧栏**：`/search` 支持跨所有工作表中文子串搜索并跳转到对应任务详情侧栏；桌面侧栏与手机窄屏（390px）均可正常查看与编辑。
6. **实时协同、在线状态与冲突保护（A13、A17、A18、A19、A20）**：他人修改在 1 秒内无需刷新即可见（含工作表、看板与我的任务）；工作表内可见在线用户与正在选中/编辑的格子，关闭页面后消失；改同一行不同字段互不覆盖，改同一字段或编辑中收到远端更新时不打断中文输入法组字、不丢草稿，并弹出提示由用户选择保留或采用；断线重连后自动补发，超限时整表刷新。
7. **权限隔离与交付**：跨项目隔离测试覆盖全部新增带 ID 接口与 `worksheet` 实时订阅；CI 全绿并部署到 VPS 验证通过。

## 4. 数据模型与迁移

主键一律 `uuid`（默认 `uuidv7()`），时间一律 `timestamptz`。所有表均含 `project_id`（外键 `projects.id`），数据访问层查询函数一律以 `projectId` 为第一必填参数。

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | `uuid` 主键 | |
| `project_id` | `uuid` 外键 `projects` | |
| `name` | `text` 非空 | 同一项目内唯一（NFC + trim 后） |
| `sort_order` | `text` 非空 | `fractional-indexing` 排序键 |
| `created_at` / `updated_at` | `timestamptz` | |

索引：唯一索引 `(project_id, name)`；普通索引 `(project_id, sort_order)`。

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | `uuid` 主键 | |

| `revision` | `integer` 非空，默认 `1` | 独立于 `tasks.revision`，每次格内修改递增 |
| `updated_at` | `timestamptz` | |

- 唯一索引 `(task_id, column_id)`
- `(project_id, worksheet_id)`

| `created_at` | `timestamptz` | |

### 4.3 字段规则与常量（`packages/shared/src/worksheet.ts`）

前后端共用同一份 Zod 定义（字符串统一做 NFC 归一化 + 去首尾空白，禁止控制字符，与阶段 1 `fields.ts` 一致）：

| 字段 | 规则 |
|---|---|
| 工作表名 / 看板列名 / 列名 | 1–32 字符，不含控制字符 |
| 工作表颜色 `color` | 固定枚举 `slate` / `red` / `orange` / `amber` / `emerald` / `teal` / `sky` / `blue` / `indigo` / `violet` / `pink` / `rose`（默认 `sky`） |
| 作品名 `work.name` | 1–80 字符，不含控制字符 |
| 任务标题 `title` | 1–200 字符，不含控制字符 |
| 分工说明 `divisionNote` | 0–500 字符（允许换行以外的普通文本，建议单行或去控制字符） |
| 优先级 `priority` | `normal`（普通）/ `high`（高）/ `urgent`（紧急） |
| 发布状态 `publishStatus` | `unpublished`（未发布）/ `published`（已发布） |
| 发布日 `publishedAt` | 可空；非空时匹配 `^\d{4}-\d{2}-\d{2}$` 且为合法日历日期 |
| 发布链接 / 自定义链接列 | 可空；非空时为合法 URL 且协议仅限 `http:` 或 `https:`，长度 ≤ 1000 |
| 自定义文本列值 | 可空；长度 ≤ 500 |
| 自定义日期列值 | 可空；`YYYY-MM-DD` 合法日期 |
| 工序状态 `stage.status` | `not_started`（未开始）/ `in_progress`（进行中）/ `done`（已完成）/ `na`（不适用） |
| 工序备注 `stage.note` | 0–200 字符 |
| 负责人列表 `stage.assignees` | 最多 20 项；用户项校验 `userId` 属于当前项目；文本项 1–32 字符；按同 `userId` 或同文本自动去重 |
| 列宽 `width` | 整数 80–600 |
| `system_columns` 结构 | `{ title?: { width?: number }, work?: { width?: number, hidden?: boolean }, divisionNote?: { width?: number, hidden?: boolean }, priority?: { width?: number, hidden?: boolean }, publish?: { width?: number, hidden?: boolean }, files?: { width?: number, hidden?: boolean } }`（`title` 永远不可隐藏、永远冻结） |

### 4.4 核心不变量

1. **看板列 1:1 映射**：同一张未删工作表内，任意 `board_column_id` 最多绑定一个未删工序列（由部分唯一索引保障；冲突时返回 `409 CONFLICT` 并提示“该看板列已绑定到其他工序列”）。
2. **删除看板列不毁数据**：删除 `board_columns` 时外键 `ON DELETE SET NULL` 自动把对应工序列改为“不上看板”，不删列也不删工序格。
3. **软删除一致性**：删除工作表或列只设 `deleted_at`；已删除工作表的任务不再出现在看板、“我的任务”和搜索结果中。
4. **排序键冲突兜底**：并发向同一位置插入行导致相同 `sort_order` 时，查询按 `(sort_order ASC, id ASC)` 保证确定性顺序；在任意两行之间插入时若 `a === b` 或键长超过 32 字符，服务端在事务内以工作表级咨询锁重整该表全部未删行的 `sort_order`（重新分配 `a0`, `a1`, ...），并广播 `tasks.reordered`。

## 5. 核心业务规则

### 5.1 建表列模板与自动映射

新建工作表时客户端可选内置模板（定义在 `packages/shared/src/worksheet.ts`），服务端按模板创建初始工序列，并按**名称完全相等**自动匹配当前项目已有的 `board_columns`：

| 模板标识 | 名称 | 初始工序列 |
|---|---|---|
| `standard_video` | 标准视频 | 时轴、翻译、校对、嵌字 |
| `song_translation` | 歌曲翻译 | 日文歌词、全曲翻译、校对、润色 |
| `magazine_manga` | 杂志 / 漫画 | 翻译、校对、嵌字、排版 |
| `blank` | 空白工作表 | （无初始工序列） |

新建完成后，用户可随时增删改列及更改其看板列映射，不再与模板绑定。

### 5.2 首页看板推导规则（纯函数，置于 `packages/shared/src/board.ts`）

所有看板判断**禁止写死任何工序名称**，完全由 `board_columns`、`column_configs` 和 `stage_cells` 实时推导：

给定项目全部 `boardColumns`（按 `sortOrder` 升序）、未删 `worksheets`、未删 `stageColumns`、未删且 `publishStatus !== 'published'` 的 `tasks` 及对应 `stageCells`：

1. **任务的适用工序**：取出该任务所在工作表的全部未删 `stage` 列（按工作表 `column.sortOrder` 升序），读取其 `StageCell`（不存在则视为默认 `not_started`、空负责人、空备注）；过滤掉 `status === 'na'` 的列，余下即为该任务的**适用工序列表**。
2. **任务的上看板适用工序**：从适用工序列表中筛出 `boardColumnId != null`（且对应看板列存在）的项，按**目标 `BoardColumn.sortOrder` 升序**排列。
3. **卡片出现在哪些看板列**：
   - 若上看板适用工序列表为空，或其中每一项均为 `done`，该任务**不出现在看板上**。
   - 否则，收集满足以下任一条件的上看板适用工序：
     - **条件 A**：`status === 'in_progress'`；
     - **条件 B**：它是上看板适用工序列表中**第一个 `status !== 'done'`** 的项。
   - 每个命中的工序对应一张该任务在其目标 `boardColumnId` 列中的卡片（因同表内工序列与看板列为 1:1 映射，同一任务在同一看板列最多出现一次）。
4. **卡片展示内容**：
   - **本列工序状态与负责人**：该卡片对应工序的 `status` 与 `assignees`（无负责人时标注“缺人”）。
   - **类型标签**：工作表 `name` 与 `color`。
   - **作品标签**：若 `work != null`，显示作品名；点击后在看板按 `(worksheetId, workId)` 筛选。
   - **缺人标签**：遍历该任务的**全部适用工序（含不上看板的工序）**，按工作表列顺序找出满足 `status !== 'done' && assignees.length === 0` 的工序，渲染为可点击的 `缺 <工序名>` 标签。
   - **进度概览**：该任务全部适用工序的 `{ name, status }` 摘要。
5. **空列保留**：没有任何卡片的看板列照常显示为空列。
6. **不可手动拖动换列**：卡片归属列完全由工序状态推导，看板上不支持拖动卡片跨列移动。

### 5.3 缺人标签点击认领（原子抢占）

`POST /api/tasks/:taskId/stages/:columnId/claim`：

1. 在 `withTx` 事务内校验 `task` 未删、所属工作表未删、`column` 是该表的未删 `stage` 列。
2. 锁定任务行（`SELECT ... FOR UPDATE`），读取对应 `stage_cells` 行（若不存在则准备插入）。
3. 校验：
   - 若 `status === 'done'` 或 `status === 'na'`，返回 `409 CONFLICT`（“该工序无需认领”）。
   - 若 `assignees.length > 0`，返回 `409 STAGE_ALREADY_CLAIMED`（`message` 形如“该工序已被 小陈 认领”），**不把当前用户追加进去**。
4. 写入 `assignees = [{ type: 'user', userId: auth.userId }]`，**保持原状态不变（通常仍为 `not_started`）**，`revision + 1`。
5. 写入 `change_logs`（`stage.updated`），并发出 `worksheet` 与 `project` 范围实时事件。

### 5.4 首页“我进行中的任务”与“我的任务”页（`/my-tasks`）

只匹配 `assignees` 中包含 `{ type: 'user', userId: auth.userId }` 的条目（纯文本名字不计入）：

- **首页顶部“我进行中的任务”**：
  - 列表项：未删工作表、未删且**未发布**任务中，由当前用户负责且 `status === 'in_progress'` 的工序条目；每条显示任务标题、工作表类型标签、作品标签（若有）、自己负责的工序名，提供“标为已完成”按钮与“打开详情”按钮。
  - 计数提示：同时统计由当前用户负责、任务未发布、且 `status === 'not_started'` 的条目数，显示“另有 N 项已认领待开始 → 前往我的任务”。
- **`/my-tasks` 页面**：
  - 分为两组展示未完成条目：**进行中**（上）、**未开始**（下），每条支持快捷把自己的工序改为“进行中 / 已完成 / 未开始”或打开任务详情侧栏。
  - 页面底部提供默认收起的折叠区 **“我已完成（N 条）”**，包含当前用户负责且 `status === 'done'` 或所属任务已发布的条目，方便回顾。

### 5.5 工作表顶部“已发布”折叠区

- 仅 `publishStatus === 'published'` 的任务归入工作表**顶部**的 **“已发布（N 条）”** 折叠区，默认收起。
- 所有工序均已标“已完成”但 `publishStatus === 'unpublished'` 的任务**不折叠**，保留在下方主表格中。
- 展开“已发布”折叠区后，行结构与主表格列完全对齐、支持完整编辑；将某行改回 `unpublished` 后自动移回下方主表格；将主表格某行改为 `published` 后自动移入顶部折叠区，并在页面右下角弹出轻量提示“已移入顶部‘已发布’折叠区”。

### 5.6 并发冲突检测与中文输入法保护（A13 / A19）

**服务端规则**：

1. **任务标量更新 `PATCH /api/tasks/:id`**：
   - 请求体：`{ changes: Partial<TaskEditableFields>, baseValues?: Partial<TaskEditableFields>, force?: boolean }`（其中 `customValues` 按 `columnId` 逐键比对，不把整个 JSONB 当作单一字段）。
   - 事务内 `SELECT ... FOR UPDATE` 锁任务行。
   - 若 `force !== true`，对 `changes` 中每一个提交的键（含 `customValues` 内的单个 `columnId`）检查：`deepEqual(currentValue, baseValues[key])`。
   - 全部通过：合并写入新值，`revision = revision + 1`，记修改记录，广播 `task.updated`。因此两人同时改同一行的不同字段（如甲改 `title`、乙改 `divisionNote`）各自独立成功，**两者都保留**（满足 A13）。
   - 任一字段不相等：回滚事务，返回 `409 FIELD_CONFLICT`，响应体附带：
     ```json
     {
       "error": {
         "code": "FIELD_CONFLICT",
         "message": "该单元格刚被他人修改",
         "details": {
           "conflicts": [
             { "field": "title", "currentValue": "新标题", "revision": 5, "updatedByDisplayName": "小陈" }
           ]
         }
       }
     }
     ```
2. **工序格更新 `PATCH /api/tasks/:taskId/stages/:columnId`**：
   - 请求体：`{ assignees?, status?, note?, baseRevision: number, force?: boolean }`。
   - 事务内锁任务行并读取工序格（不存在则 `currentRevision = 0`）。
   - 若 `force !== true && currentRevision !== baseRevision`，返回 `409 FIELD_CONFLICT`，在 `details` 中带回服务端最新 `stageCell` 与最后修改人显示名。
   - 通过则更新并 `revision = currentRevision + 1`，记修改记录，广播 `stage.updated` 与 `board.task_changed`。

**前端交互规则**：

1. **中文输入法组字保护**：所有文本单元格监听 `compositionstart` / `compositionend`；组字期间 `isComposing = true`，禁止按 Enter 提前提交、禁止远端事件回写输入框。
2. **编辑中收到远端更新（A19）**：
   - 客户端维护当前正在编辑的单元格标识 `activeEditor = { taskId, columnKey }`。
   - 收到非本连接发出的实时事件时：
     - 若事件命中的不是 `activeEditor`，直接把最新值合并到缓存并渲染。
     - 若事件正好命中 `activeEditor`，**不覆盖输入框中用户正在打的草稿**，而是在该单元格旁渲染非打断式冲突浮条：`{actorDisplayName} 刚把此格改为「{formattedValue}」 [保留我的] [采用对方的]`。
     - 点“保留我的”：携带 `force: true` 提交当前草稿并关闭浮条；点“采用对方的”：丢弃草稿、应用远端最新值并关闭浮条。
3. **提交遇 `409 FIELD_CONFLICT`**：保留用户草稿不清空，展示完全相同的冲突浮条（保留我的 / 采用对方的）。
4. **保存失败（网络/5xx）**：保留草稿，单元格标红并提示“保存失败，点击重试”。

### 5.7 修改记录与一键恢复

在业务写入的同一个 `withTx` 事务中插入 `change_logs`：

| `action` | 触发场景 | `changes` 载荷 |
|---|---|---|
| `task.created` | 新建任务 | `{ title, workName? }` |
| `task.updated` | 修改任务标量或自定义列 | `{ diffs: [{ field, label, from, to }] }` |
| `task.deleted` | 软删除任务 | `{ snapshot: { task, stageCells } }`（含删前标题、作品名、分工说明、各工序摘要，便于界面展示） |
| `task.restored` | 从修改记录恢复任务 | `{ title }` |
| `stage.updated` | 修改工序格或认领 | `{ columnId, columnName, diffs: [{ field, label, from, to }] }` |
| `worksheet.created` / `worksheet.updated` / `worksheet.deleted` | 工作表结构变化 | `{ name, diffs? }` |
| `column.created` / `column.updated` / `column.deleted` | 列增删改（列宽/显隐高频拖动仅在松手保存时记录，且只记实际变化的字段） | `{ columnId, name, diffs? }` |
| `board_column.updated` | 看板列增删改排序 | `{ detail }` |

**恢复规则**：
- 工作表“修改记录”抽屉中，对于 `action === 'task.deleted'` 且当前对应任务仍处于 `deleted_at IS NOT NULL` 状态的记录，显示 **“恢复”** 按钮（若已被恢复则显示“已恢复”徽章）。
- 点击调用 `POST /api/tasks/:id/restore`：校验所属工作表未被删除、置 `deleted_at = null`、`revision + 1`、写 `task.restored` 记录、广播 `task.restored` 与 `board.task_changed`。

### 6.3 在线状态（Presence）协议

落地阶段 1 预留的 `t: 'presence'` 消息，全部只存服务端内存（`apps/server/src/realtime/presence.ts`），**不写 `realtime_events`、不入库、不参与游标与补发**。

**客户端 → 服务端**：

```json
{
  "t": "presence",
  "scope": { "type": "worksheet", "id": "<worksheetId>" },
  "focus": { "taskId": "<taskId>", "columnKey": "title | work | divisionNote | priority | publish | <columnId>", "editing": true }
}
```
离开单元格时发 `focus: null`。仅在已订阅该 `worksheet` 时生效，否则忽略。

**服务端 → 客户端**：

| `t` | 字段 | 说明 |
|---|---|---|
| `presence_snapshot` | `scope`，`peers: Array<{ connId, userId, displayName, focus }>` | 客户端订阅 `worksheet` 成功后立即下发当前在线成员（不含自己） |
| `presence_update` | `scope`，`peer: { connId, userId, displayName, focus }` | 有新连接加入或焦点变化时广播给同范围其他连接 |
| `presence_leave` | `scope`，`connId` | 连接取消订阅、关闭、心跳超时或会话失效时广播给同范围其他连接 |

**颜色分配**：前端按 `userId` 的稳定哈希从 8 种高对比度协作色中取值，保证所有人在同一工作表里看到的同一用户边框颜色一致。用户关闭页面、切换工作表或断线后，服务端立即触发 `presence_leave`，界面标记随即消失（满足 A18）。

## 7. HTTP 接口清单

沿用阶段 1 约定：前缀 `/api`、JSON 收发、非 GET 写请求校验 `Origin`、错误码统一放在 `packages/shared/src/errors.ts`。

本阶段在 `ERROR_CODES` 新增两个 409 错误码（并在 `ErrorBody` 中增加可选 `details?: unknown`）：
- `409 FIELD_CONFLICT`：字段或工序格并发冲突（`details` 含冲突字段与服务端最新值）
- `409 STAGE_ALREADY_CLAIMED`：缺人认领时工序已被他人抢先认领

所有新增接口的访问级别均为 `authenticated` 或 `{ permission: 'worksheets.manage' }`（按 ADR-0003 二者均允许管理员与普通用户，保留 `worksheets.manage` 标记便于结构接口归类）。**不得新增任何 `public` 接口。**

### 7.1 看板列

| 方法与路径 | 访问 | 请求 | 响应与说明 |
|---|---|---|---|

## 8. 前端架构与页面设计

仅简体中文，桌面端与手机端（390px 窄屏）共用同一套页面。

### 8.1 路由与导航变更

在 [apps/web/src/app/App.tsx](../apps/web/src/app/App.tsx) 与 [AppShell.tsx](../apps/web/src/app/AppShell.tsx) 中调整：

- **移除** `/archive` 路由与左侧导航中的“归档”项。
- **更新**导航结构：
  - 顶部主导航：`首页`（`/`）、`我的任务`（`/my-tasks`）、`资源检索`（`/search`）、`参考资料`（`/references`，仍占位）
  - **工作表分组**：标题旁带“全部 / 新建”入口（指向 `/worksheets`），下方实时列出所有未删工作表（每项带标签色点 + 工作表名，点击进入 `/worksheets/:id`；订阅 `project` 范围收到 `worksheet.changed` 时自动刷新）。
  - 底部：`个人设置`（`/settings`），管理员另见 `用户与邀请`、`存储`（占位）、`实时通道诊断`。
- **调整主容器宽度**：工作表与看板页需要更宽的横向空间，将 `AppShell` 中 `<main>` 的 `max-w-5xl` 改为按页面布局（工作表与看板使用全宽 `w-full`，设置与管理页维持合适最大宽度）。

### 8.2 页面规格

#### 1. 首页看板（`/`）

- **订阅**：进入页面先订阅 `project` 范围并等 `subscribed`，再请求 `GET /api/board`；收到 `board.task_changed` / `board_columns.changed` / `worksheet.changed` / `user.updated` 时防抖刷新（150ms）。
- **顶部“我进行中的任务”条**：
  - 列出 `myInProgress`；每项显示工作表类型标签、作品标签（若有）、任务标题、自己负责的工序名、**“完成”**按钮（直接把该工序置为 `done`）与**“详情”**按钮。
  - 右侧显示“另有 N 项待开始”，点击进入 `/my-tasks`。若无进行中条目，折叠为紧凑一行不占首屏。
- **筛选栏**：按工作表（类型）、按作品、仅看缺人、仅看与我有关；另有当前激活的作品筛选芯片（点击卡片上的作品标签即激活，点 `×` 清除）。
- **看板主体**：横向排列所有 `boardColumns`（手机端可左右滑动）；每列顶部显示列名与卡片数量，空列照常展示。
- **任务卡片**：
  - 顶部标签行：工作表类型标签（固定色）+ 作品标签（可点击筛选）+ 优先级徽章（仅高/紧急显示）。
  - 标题 + 分工说明（若有，单行截断）。
  - 本列工序状态行：如 `小陈 · 进行中` 或 `未开始 · 缺人`。
  - 缺人标签区：列出所有缺人的适用工序（含不上看板工序），形如 `+ 缺 校对`；点击直接调用认领接口（带防抖/加载态），成功立即刷新，遇 `409 STAGE_ALREADY_CLAIMED` 弹 Toast 提示并刷新。
  - 底部：全部适用工序的迷你进度点（绿=完成、蓝=进行中、灰=未开始）；点击卡片空白处打开**任务详情侧栏**。

#### 2. 我的任务（`/my-tasks`）

- 订阅 `project` 范围，收到变更自动刷新。
- 按 **进行中**、**未开始** 分组列出当前用户负责的未完成工序；每条可直接用状态下拉/快捷按钮切为“进行中 / 已完成 / 未开始”，或点击打开任务详情侧栏 / 跳到对应工作表行。
- 底部提供默认折叠的 **“我已完成（N 条）”** 区块，展开回顾已完成的工序与已发布的任务。

#### 3. 工作表总览与配置（`/worksheets`）

- **工作表列表**：展示所有未删工作表（颜色点、名称、未发布/总任务数），支持拖动调整工作表顺序、新建工作表（名称 + 颜色 + 4 套模板选择）、重命名/改色、二次确认删除工作表。
- **项目级看板列配置**：展示当前看板列顺序，支持拖动排序、新增看板列、改名、删除（提示已绑定的工序列会变为不上看板）。

#### 4. 单张工作表（`/worksheets/:id`）

这是阶段 2 的核心交互页面：

- **先订阅后读数据**：进入页面先向 `RealtimeClient` 订阅 `worksheet:{id}`，等到 `subscribed` 后再请求 `GET /api/worksheets/:id`；收到 `resync` 时整表重拉。
- **顶部工具栏**：
  - 工作表名 + 颜色点（点击可编辑）
  - **在线用户头像条**：显示同表在线的其他用户（按 `userId` 去重，悬停显示显示名与正在看的格子），颜色与格子边框一一对应。
  - 操作按钮：`+ 新建任务`、`列设置`（管理工序列/自定义列的增删改、排序、显隐、看板映射）、`修改记录`（打开右侧修改记录抽屉）。
- **筛选与排序栏**（纯前端本地态，不落库、不同步）：
  - 快捷状态芯片：`全部` / `我的` / `未开始` / `进行中` / `全工序已完成`
  - 负责人下拉筛选（支持项目用户与表中已有的纯文本名字）、作品筛选、关键词搜索
  - 排序选择（默认手动顺序 / 按标题 / 按优先级 / 按作品）；当启用非默认排序或筛选时，禁用行拖动并显示小字提示“恢复默认顺序后可拖动调整行序”。
- **顶部“已发布”折叠区**：
  - 若当前工作表存在 `publishStatus === 'published'` 的任务，在主表上方展示折叠条 **`已发布（N 条）`**（默认收起）。
  - 展开后复用同一套表格列与内联编辑交互，与下方未发布主表对齐；把任务从已发布改回未发布时即时移回主表，反之即时移入折叠区并弹轻量提示。
- **核心表格（TanStack Table v9 + `@dnd-kit`）**：
  - **冻结列**：左侧拖动手柄 + **标题列**使用 `position: sticky; left: 0` 冻结，横向滚动时保持固定。
  - **列宽拖动**：每个列头右侧提供拖拽把手，拖动即时预览，松手后调用 `PATCH` 持久化列宽并同步给他人。
  - **单元格交互**：
    - **标题 / 分工说明 / 自定义文本列**：单击选中（上报 `focus: { editing: false }`），双击或按 Enter 进入编辑态（上报 `editing: true`）；支持真实中文输入法（`compositionstart/end` 保护）；失焦或 Enter 提交，Esc 取消。
    - **所属作品**：点击弹出 Combobox，列出当前工作表已有作品，支持搜索、点击选择、直接输入新名称回车创建、清空、以及行内重命名作品。
    - **工序格**：合并显示负责人与状态（如 `小陈 · 进行中`，带语义色块；有备注时带小图标悬停显示）；点击弹出 Popover：多选项目用户 + 输入自由纯文本名字回车添加 + 切换 4 种状态 + 编辑备注；关闭或点击保存提交。
    - **优先级**：点击下拉选择 普通 / 高 / 紧急。
    - **发布信息**：显示“未发布”或“已发布 · 日期 · 链接图标”；点击弹出 Popover 切换发布状态、选日期、填发布链接（外链以 `target="_blank" rel="noopener noreferrer"` 打开）。
    - **文件列（阶段 2 占位）**：显示“阶段 3 启用”轻量图标/按钮，点击打开任务详情侧栏。
    - **行操作**：悬停行显示“在下方插入行”“打开详情”“删除任务”（删除直接软删除并弹 Toast 附“撤销”按钮调用 `/restore`）。
  - **他人焦点与冲突呈现**：
    - 他人选中的格子显示对应用户颜色的 2px 边框 + 右上角小名牌；`editing: true` 时名牌显示“某某 正在编辑”。
    - 正在编辑的格子收到远端变更或提交遇 `409 FIELD_CONFLICT` 时，在格子下方贴附冲突提示条（不销毁草稿），提供 **[保留我的]** 与 **[采用对方的]** 两个按钮。
- **定位高亮**：从首页看板、我的任务或检索页带 `?taskId=<id>` 跳转进入时，自动展开折叠区（若该行已发布）、滚动到对应行并高亮闪烁 2 秒，同时打开任务详情侧栏。

#### 5. 任务详情侧栏（组件，供看板 / 我的任务 / 工作表 / 检索共用）

- 桌面端从右侧滑出（宽约 440px），手机端全屏抽屉。
- 内容区：所属工作表标签、可编辑标题/所属作品/分工说明/优先级/发布信息、全部工序列卡片（可直接改负责人/状态/备注）、自定义列、**文件区占位**（提示“任务文件与网盘入口将在阶段 3 启用”）、以及可展开的**本任务修改记录**。
- 顶部提供 **“在工作表中定位”** 按钮（跳转到 `/worksheets/:worksheetId?taskId=:taskId`）。

#### 6. 资源检索页（`/search`）

- 顶部搜索框（支持中文关键词，300ms 防抖）+ 工作表下拉筛选 + 工序状态筛选 + “隐藏已发布”复选框（默认不勾选，即包含已发布任务）。
- 结果列表每条显示：任务标题、工作表标签、作品标签、分工说明片段、匹配到的负责人与各工序状态摘要；点击直接跳到 `/worksheets/:worksheetId?taskId=:taskId` 打开详情侧栏。
