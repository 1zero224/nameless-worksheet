## 1. 目标与退出条件

阶段 4 打通“在工作表/看板/通用文档上传文件到私有 R2 → 断点续传与指纹可观测 → 自动生成/更新版本 → 实时可见 → 一键授权下载（还原中文文件名）与安全在线预览”的完整文件闭环，实现首个核心里程碑：**登录 → 打开工作表 → 改负责人或状态 → 上传文件到 R2 → 看到新版本 → 下载旧版本 / 预览文件**。

退出条件（全部满足才算完成，逐条对应第 10 节验收清单）：

1. **单次与分片直传闭环（A01 / A02 / A11）**：支持在四级挂载点（通用文档 `/docs`、作品大标题横幅、任务行、工序格）新建资源上传文件、给已有资源上传新版本、以及给尚无 R2 文件的已有版本补传文件（不升版本号）；文件字节由浏览器直传 R2，不经业务服务器中转；≤ 10 MiB 走单次 PUT 并跳过上传前指纹，> 10 MiB 走分片上传（默认 10 MiB/片、并发 3，均环境变量可配）；两次上传同名文件各自生成独立随机 key 与独立版本，旧版字节完整保留，新版完成后立即成为最新；伪造会话、跨会话 key、虚报大小、未完成上传或过期签名均无法生成有效版本。
2. **断点续传、指纹可观测与取消清理（A04 / A16）**：大文件（> 10 MiB）在独立 Web Worker 中流式分块计算 SHA-256（不卡主线程、不整文件入内存），全程展示实时进度与已处理体积、可随时取消、15 秒无进展明确超时提示，并提供「跳过续传检查，直接重新上传」逃生按钮；短暂断网仅重传失败分片；刷新页面后队列展示待续传记录，重选同一本地文件通过指纹核对 + `ListParts` 复用已完成分片（大小相同内容不同的文件绝不误恢复）；取消上传以服务端 `AbortMultipartUpload` 成功为准，R2 不残留未完成分片。
3. **并发安全、幂等与冲突保护（A05）**：两人并发给同一资源上传各自生成递增版本互不覆盖；重复提交同一会话的完成请求幂等返回同一结果、只生成 1 个版本；未完成或失败上传绝不改变 `latest_version_id`；两人并发给同一“尚无 R2 文件版本”补传文件时，后完成者收到 `409 CONFLICT` 且界面支持一键将已传字节「改存为新版本（vN+1）」或取消释放，绝不静默覆盖也不白传。
4. **授权下载与在线预览（A06 / A15）**：私有 R2 字节必须经业务 API 鉴权签发短期 GET 地址方可访问；下载强制 `Content-Disposition: attachment` 并按 RFC 5987 精确还原中文/特殊字符原始文件名，支持浏览器与下载器 HTTP `Range` 断点下载；任意保留的历史版本均可下载；在线预览直连 R2 短期预签名 GET（支持 `Range` 拖动），覆盖安全文本（ASS/SRT/TXT/VTT/LRC，≤ 5 MiB，自动探测与手动切换 UTF-8/UTF-16/GB18030/Shift-JIS 编码、带行号转义只读）、安全栅格图片（禁用 `.svg` 内联预览）及浏览器原生音视频（解码失败优雅降级提示下载），PSD/字体/压缩包仅显示元数据与下载。
5. **同版本文件与多网盘共存及软删恢复（A03 / A09）**：同一版本可同时挂载 1 份 R2 文件与 0..N 条网盘链接，R2 行与多网盘行并列展示互不干扰；单独软删 R2 入口或网盘入口互不影响且支持 Toast 撤销与修改记录恢复；软删最新版回退显示剩余最高版本；阶段 4 不物理删除软删版本的 R2 字节，仅通过 `pg-boss` 后台定时清理超过宽限期的过期/已取消未完成分片与孤立对象。
6. **融合检索、实时同步、移动端与安全（A07 / A17 / A27）**：`GET /api/search` 扩展匹配未删版本的原文件名；上传进度不广播，仅在保存成功后广播 `artifact.changed`（仅 ID，零签名 URL / R2 key / 提取码），他人 1 秒内实时可见；全局右下角上传队列浮窗跨路由不中断，桌面（1440×900）与手机窄屏（390×844）均可用且切后台返回可续传；CI 全绿并部署至香港 VPS 接通真实 Cloudflare R2 完成小文件与 25–50 MiB 分片全链路实测。

## 4. 数据模型与迁移

主键一律 `uuid`（`uuidv7()`），时间一律 `timestamptz`。所有表均含 `project_id`（外键 `projects.id`），查询层一律以 `projectId` 为第一必填参数。

### 4.1 新增枚举与表结构

#### 新增枚举

- `upload_session_mode`: `'create_artifact' | 'create_version' | 'attach_version'`
- `upload_session_status`: `'uploading' | 'completed' | 'aborted' | 'expired'`

#### `blobs`（实际存储在 R2 的不可变字节对象）

| 列 | 类型 | 说明 |
|---|---|---|

1. **服务端唯一权威**：`r2_key`、`r2_upload_id`、`size_bytes`、目标 `worksheetId/workId/taskId/stageColumnId/artifactId/versionId` 全部以服务端 `upload_sessions` 行记录为准；签名、完成、取消接口全部校验 `session.projectId === auth.projectId && session.createdBy === auth.userId`。
2. **完成校验双关卡（A11）**：
   - 分片会话：服务端先调用 R2 `ListParts(session.r2Key, session.r2UploadId)` 获取全部已上传分片并按 `PartNumber` 升序校验（绝不信任客户端传来的 ETag 列表），确认无缺片且总大小等于 `session.sizeBytes` 后，由服务端调用 `CompleteMultipartUpload`；
   - 单次 PUT 与分片合并后：服务端一律调用 R2 `HeadObject(session.r2Key)`，校验对象真实存在且 `ContentLength === session.sizeBytes`；不符立即拒绝并不写业务版本表。
3. **版本原子性与并发安全（A02 / A05）**：
   - `complete` 在 `withTx` 事务内先 `SELECT ... FROM upload_sessions WHERE id = $1 FOR UPDATE` 锁会话行；
   - 若 `session.status === 'completed'`，直接按 `result_*` 查询并返回已创建的完整 DTO（**严格幂等**，重复点完成只生成 1 个版本）；
   - 若 `session.status === 'aborted'` 或已过期且未完成，返回 `409 CONFLICT` / `410 GONE`；
   - `create_version` 模式下再 `SELECT ... FROM artifacts WHERE id = $1 FOR UPDATE` 锁资源行，分配 `MAX(version_number) + 1`，插入 `blobs` + `artifact_versions`（同步写入 `original_filename / size_bytes / mime_type`）+ `resource_locations(type='r2', blob_id)`，更新 `artifacts.latest_version_id`；
   - `attach_version` 模式下锁 `artifact_versions` 行，检查是否存在未删 `type='r2'` 的 `resource_locations`：
     - 若无：插入 `blobs` + `resource_locations(type='r2', blob_id)`，回填 `artifact_versions.original_filename / size_bytes / mime_type`（不升版本号）；
     - 若已有（并发补传冲突，Q9）：**先将已核验的 R2 对象落库为 `blobs` 并记入 `session.result_blob_id`**（保持会话状态为 `uploading` 以便转存，不浪费已传字节），抛出 `409 CONFLICT`（错误码 `VERSION_ALREADY_HAS_FILE`，消息“该版本已由他人上传文件，可将本次已传文件改存为新版本”）；前端提供一键调用 `POST /api/uploads/sessions/:id/promote-to-version` 复用该 `result_blob_id` 直接创建新版本 `vN+1`！
4. **文件名清洗与还原（A15）**：
   - 保留中文、日文、韩文、空格与常见符号；去除前导/尾随空白、控制字符、路径分隔符（`/`、`\`）与 `..`，超长截断至 255 字符（保留扩展名）；空文件名兜底 `untitled`。
   - 下载签发时构造 RFC 5987 Header：
     ```text
     Content-Disposition: attachment; filename="<ascii-fallback>"; filename*=UTF-8''<rfc5987-encoded-original>
     ```
5. **只软删不物理删（A09）**：阶段 4 软删资源、版本或 `r2` 入口时绝不调用 R2 `DeleteObject`，保证修改记录可随时完整还原；同一 `blob_id` 如有其他版本引用（或阶段 6 清理前）均按引用计数保护。

### 5.2 双驱动实现

1. **`R2StorageDriver`（`apps/server/src/storage/r2.ts`）**：
   - 使用 `@aws-sdk/client-s3` 初始化 `S3Client({ region: 'auto', endpoint: config.r2Endpoint, credentials: { accessKeyId, secretAccessKey }, forcePathStyle: false })`；
   - 预签名使用 `@aws-sdk/s3-request-presigner` 的 `getSignedUrl`；
   - 注意 AWS SDK v3 默认对 `PutObject` / `UploadPart` 注入自动校验和中间件，与 Cloudflare R2 浏览器直传可能产生签名头不匹配：初始化 `S3Client` 时显式设置 `requestChecksumCalculation: 'WHEN_REQUIRED'`、`responseChecksumValidation: 'WHEN_REQUIRED'`，确保浏览器 `PUT` 与 R2 100% 兼容；
   - `listParts` 循环处理 `IsTruncated` / `NextPartNumberMarker`，保证超过 1,000 片的大文件也能完整拉齐；
   - `abortMultipartUpload` 遇 `NoSuchUpload` 视为已清理成功（幂等）。
2. **`LocalStubStorageDriver`（`apps/server/src/storage/local-stub.ts`）**：
   - 仅用于 `STORAGE_DRIVER=local`（本地无 R2 凭据开发、Vitest 集成测试与 Playwright E2E）；
   - 启动一个仅监听 `127.0.0.1` 随机端口的轻量 Node HTTP 服务，将字节存入临时目录，用 HMAC-SHA256 校验预签名 `exp` 与参数（过期或无签名一律返回 `403`）；
   - 完整实现：CORS 预检 `OPTIONS` 与 `Access-Control-Expose-Headers: ETag, Content-Range, Accept-Ranges, Content-Length`、单次 `PUT`、分片 `PUT ?uploadId=&partNumber=` 返回真实 `ETag`、`GET` 支持 `Range: bytes=...` 返回 `206 Partial Content`、`ResponseContentDisposition` 与 `ResponseContentType` 回写、`Abort` 后清理临时分片并让后续 `ListParts` 抛 `NoSuchUpload`。

## 6. 核心业务规则与安全红线

### 6.1 上传与续传状态机

1. **小文件（`size <= 10 MiB`）**：
   - 前端跳过上传前 SHA-256 计算，直接调用 `POST /api/uploads/sessions`（`fingerprintSha256: null`）；
   - 服务端校验权限、目标挂载点未删、大小 ≤ 10 GiB，生成随机 `r2_key` 与 10 分钟单次 `PUT` 签名 URL 返回；
   - Uppy 直传 `PUT` 到 R2 → 前端调用 `POST /api/uploads/sessions/:id/complete` → 服务端 `HeadObject` 核验存在与大小一致 → 事务落库并广播 `artifact.changed`。
2. **大文件（`size > 10 MiB`）**：
   - **阶段 A（指纹计算，A16）**：进入独立 Web Worker 用 `hash-wasm` 以 **4 MiB 分块**流式读取文件算 SHA-256：
     - 每块汇报 `{ processedBytes, totalBytes, percent }`，UI 实时显示进度条；
     - 随时可点「取消」（立即中止 Worker 与 `AbortController`）；
     - 内置 **15 秒卡顿看门狗**（连续 15 秒无新分块回报则立即报错提示“读取本地文件超时，可能磁盘休眠或被占用”，给出「重试」与「跳过续传检查，直接重新上传」按钮）；
     - 随时也可主动点「跳过续传检查，直接重新上传」（`skipResume: true`，不再等待哈希，直接建全新分片会话开传）。
   - **阶段 B（会话创建或断点复用，A04）**：
     - 携带 `fingerprintSha256`、`sizeBytes`、`target` 调用 `POST /api/uploads/sessions`；
     - 若存在同一用户、同一目标、同一 `sizeBytes` 且同一 `fingerprintSha256` 的未过期 `uploading` 会话，且前端未传 `skipResume: true`：服务端直接复用该会话（`resumed: true`），并返回最新 `ListParts` 结果（**若 R2 返回 `NoSuchUpload`，自动作废旧会话并新建会话，绝不让用户永久卡死**）；
     - 大小相同但指纹不同：绝不复用，新建独立会话（A04）。
   - **阶段 C（分片上传）**：
     - `@uppy/aws-s3` 跳过 `ListParts` 中已存在且大小匹配的分片，仅对其余分片按需调用 `POST /api/uploads/sessions/:id/parts/:partNumber/sign` 获取 10 分钟短期签名直传 R2（因此即使总耗时数小时也绝不因签名过期中断），并发 3，短暂断网自动指数退避重传失败分片。
   - **阶段 D（校验与提交）**：
     - 传输 100% 后 UI 切换为 **「校验中」**，调用 `POST /api/uploads/sessions/:id/complete`；
     - 服务端 `ListParts` → 校验完整 → `CompleteMultipartUpload` → `HeadObject` 核对总大小 → 事务建 `blobs` / 版本 / `r2` 入口并更新 `latest_version_id` → 广播 `artifact.changed`；UI 切换为 **「已保存」** 并清除本地断点记录。
3. **取消（A04）**：
   - 用户点取消 → 前端先中止进行中的浏览器 XHR/Fetch，再调用 `POST /api/uploads/sessions/:id/abort`；
   - 分片会话由服务端调用 R2 `AbortMultipartUpload`；**仅当 R2 Abort 成功（或 `NoSuchUpload`）后才将状态置为 `aborted` 并返回 200**；若 R2 Abort 网络异常返回 `502`，前端明确提示“云端取消失败，请点击重试取消”，并保留在队列中允许重试（后台清理作业也会在宽限期后兜底回收）。

### 6.2 下载与在线预览规则

#### 授权下载（`GET /api/resource-locations/:id/download`）

- 校验已登录 + `location.projectId === auth.projectId` + `location.type === 'r2'` + 入口/版本/资源/父任务/父工作表均未软删（否则 404）；
- 签发 10 分钟有效 R2 GET URL，带 `ResponseContentDisposition: attachment; filename="..."; filename*=UTF-8''...`（精确还原 `artifact_versions.original_filename`，A15）；
- 返回 `302 Found`，`Location: <presignedUrl>`，附 `Cache-Control: no-store`、`Referrer-Policy: no-referrer`；
- 浏览器通过 `<a href="/api/resource-locations/:id/download">` 直触发下载，**零弹窗拦截（兼容 iOS Safari）、零 VPS 流量中转、原生支持 HTTP `Range` 断点下载**。

#### 在线预览白名单（`GET /api/resource-locations/:id/preview-url`）

服务端根据清洗后的文件扩展名（优先）与 MIME 判定 `previewKind`：

| `previewKind` | 匹配扩展名 | 规则与安全策略 |
|---|---|---|
| `text` | `.ass` `.ssa` `.srt` `.txt` `.vtt` `.lrc` `.json` `.xml` `.md` `.log` | 若 `sizeBytes > 5 * 1024 * 1024`（5 MiB）返回 `tooLargeForPreview: true` 且不签发预览 URL；否则签发短期 GET URL（不设 `attachment`），前端 `fetch` 原始字节后探测 BOM / UTF-8 有效性 / 常见日文与中文编码，提供 **自动 / UTF-8 / GB18030 / Shift-JIS / UTF-16LE / UTF-16BE** 编码切换下拉，转义为纯文本带行号只读渲染（绝不改原字节、绝不执行 HTML） |
| `image` | `.png` `.jpg` `.jpeg` `.webp` `.gif` `.avif` `.bmp` | 签发短期 GET URL（设置对应安全 `ResponseContentType`），前端 `<img>` 内联展示（支持缩放查看）；**明确排除 `.svg`**（按 `unsupported` 处理，强制附件下载，杜绝脚本注入） |
| `video` | `.mp4` `.webm` `.mov` `.m4v` | 签发短期 GET URL，前端 `<video controls playsInline>` 原生播放（R2 原生支持 Range 拖动）；捕获 `onError`（如 H.265/MKV/FLAC 编码不支持）时展示友好提示与一键「下载文件」按钮 |
| `audio` | `.mp3` `.wav` `.ogg` `.m4a` `.aac` `.flac` `.opus` | 签发短期 GET URL，前端 `<audio controls>` 原生播放；不支持时同样降级提示下载 |
| `unsupported` | `.mkv` `.avi` `.psd` `.ttf` `.otf` `.ttc` `.woff2` `.zip` `.rar` `.7z` `.svg` 及其他全部类型 | 不签发内联预览 URL，弹窗或行内直接显示原文件名、大小、MIME 与「下载文件」按钮 |

### 6.3 后台清理作业（`apps/server/src/jobs/cleanup-uploads.ts`）

在 `startJobs` 注册定时任务 `cleanup-expired-uploads`（cron `*/30 * * * *`）：
1. **清理过期与未完成取消的上传会话**：
   - 先将 `status = 'uploading' AND expires_at < NOW()` 的会话更新为 `status = 'expired'`；
   - 查询 `status IN ('expired', 'aborted') AND cleaned_up_at IS NULL` 且过期/取消时间已超过 `config.uploadCleanupGraceHours`（默认 2 小时）的会话：
     - 若 `is_multipart && r2_upload_id`：调用 `storage.abortMultipartUpload`（`NoSuchUpload` 视为成功）；
     - 若 `!is_multipart`（或单次 PUT 已传字节但未完成确认）：检查 `blobs` 表确认 `r2_key` 无任何引用后调用 `storage.deleteObject`；
     - 成功后标记 `cleaned_up_at = NOW()`。
2. **孤立对象巡检**：
   - 扫描 `storage.listObjectsByPrefix('projects/')`，仅对 `lastModified` 早于 `NOW() - (uploadSessionTtlHours + uploadCleanupGraceHours)`（默认 26 小时）的对象，核对数据库确认**既不在 `blobs.r2_key` 中，也不在任何未清理的 `upload_sessions.r2_key` 中**，方才调用 `storage.deleteObject`；
   - **硬约束**：只要 `blobs` 表存在记录（即使对应 `artifact` / `version` / `location` 已被软删），绝不删除该对象（留待阶段 6 管理员存储页手动清理）。

### 6.4 实时通道、搜索与修改记录

- **实时通道**：上传过程中绝不广播进度；`complete` 与 `promote-to-version` 事务提交后复用现有 `artifact.changed`（`scopeKind`、`action: 'artifact.created' | 'version.created' | 'location.created'`、仅传 ID）与 `board.task_changed`（`action: 'artifact.changed'`），他人 1 秒内自动刷新（A17）。
- **融合检索（`GET /api/search`）**：在阶段 3 匹配资源名 `artifacts.name` 基础上，补充匹配所有未删版本 `artifact_versions.original_filename`（覆盖通用文档、作品共用、任务级与工序格资源）；**严禁匹配或返回 `r2_key`、签名 URL、`extract_code` 或网盘 `url`**。
- **修改记录**：`artifact.created` / `artifact_version.created` / `location.created`（`type: 'r2'`）仅记录 `{ artifactId, versionId, locationId, name, versionNumber, originalFilename, sizeBytes, storageType: 'r2' }`，绝不写入 `r2Key` 或签名 URL。
- **Pino 日志脱敏**：`apps/server/src/app.ts` 在 `redact.paths` 中补充 `'res.headers.location'`，确保 `302` 重定向至 R2 预签名地址绝不落盘到访问日志。

## 8. 前端架构与页面交互设计

严格延续现有极简中性视觉体系（纯白画布、炭黑文字、`rgba(0,0,0,0.08)` 细边框、单行 44px 顶栏、`shadcn/ui` + `sonner`、桌面 1440×900 与手机 390×844 一致可用）。

### 8.1 Web Worker 流式指纹（`apps/web/src/workers/fingerprint.worker.ts` & `uploads/fingerprint.ts`）

- 文件 `size <= config.multipartThresholdBytes`（默认 10 MiB）：**跳过指纹**直接进入上传。
- 文件 `size > config.multipartThresholdBytes`：
  - 启动 `fingerprint.worker.ts`，调用 `createSHA256()`（`hash-wasm`），按 **4 MiB** 步进使用 `file.slice(offset, end).arrayBuffer()` 流式更新哈希，绝不将整文件载入内存；
  - 每块向主线程 `postMessage({ type: 'progress', processedBytes, totalBytes })`；
  - 主线程内置 **15 秒卡顿看门狗**：每收到进度重置计时器；若 15 秒无进展立即中止 Worker 并回调 `STALL_TIMEOUT`，UI 展示明确错误提示与「重试」「跳过续传检查，直接重新上传」按钮；
  - 用户点击「取消」或「跳过续传」立即 `worker.terminate()`，零残留占用。

### 8.2 Headless Uppy 全局上传管理器与队列浮窗（`UploadManagerContext.tsx` & `UploadQueueDock.tsx`）

- 底层用 `@uppy/core` + `@uppy/aws-s3`（自定义 `shouldUseMultipart`、`getUploadParameters`、`createMultipartUpload`、`listParts`、`signPart`、`completeMultipartUpload`、`abortMultipartUpload` 全部桥接到第 7.1 节服务端接口），**完全不引入 `@uppy/dashboard` UI 与样式**。
- **状态清晰区分**：`fingerprinting`（计算指纹 + 百分比 + 跳过续传/取消）→ `uploading`（上传中 + 进度条/已传大小/速度/预计剩余时间 + 取消）→ `verifying`（校验中，提示“传输已完成，正在服务端校验并保存版本”）→ `completed`（已保存，自动触发 `invalidateArtifactQueries` 刷新四级 UI）→ `conflict`（`409 VERSION_ALREADY_HAS_FILE`，提供「改存为新版本」「取消」）→ `error`（失败原因 + 重试/取消）→ `resumable`（刷新后从 `localStorage` 恢复的未过期分片记录，提示「刷新中断 · 重选原文件继续上传」+ 隐藏 `<input type="file">` 一键重选）。
- **跨路由持久化与离开保护**：`UploadQueueDock` 挂载在 `App.tsx` 根层，位于屏幕右下角（桌面宽 360px 可折叠为紧凑药丸「上传中 1/2 · 45%」；手机 390×844 窄屏贴底居中全宽无横向溢出）；有活跃上传时注册 `window.onbeforeunload` 防误关页面；用户切换工作表、看板、通用文档均不中断上传。
- **失效会话自动自愈**：刷新后点击续传若服务端返回 `404`/`410`/`409`（已过期、已取消或已在别处完成），自动清理对应 `localStorage` 记录并明确提示重新开始上传，绝不死循环报错。

### 8.3 新建资源、更新版本与补传文件弹窗

1. **`CreateArtifactModal`（新建资源）**：
   - 保留顶部亮色层级归属标签（`artifact-scope-tags`）与阶段 3 的默认资源名逻辑（工序格自动预填「作品名-任务名-工序」）；
   - 顶部增加两段式切换：**「上传文件」（默认）** \| **「网盘链接」**；
   - 「上传文件」模式：`FileDropzone`（拖拽/点选 1 个文件，超 10 GiB 当场拦截提示改用网盘）+ 资源名称（**仅当名称输入框为空时**自动按所选文件名预填，不覆盖工序格预填的「作品名-任务名-工序」）+ 单个可选「备注」；点「开始上传」立即入队右下角 `UploadQueueDock` 并关闭弹窗，不锁界面；
   - 「网盘链接」模式：100% 保留阶段 3 现有分享文本解析与精简表单。
2. **`CreateVersionModal`（更新版本）**：

3. **给无 R2 文件的已有版本补传文件（`AttachFileToVersionModal`）**：
   - 当某版本尚无未删 R2 文件时，在资源 `···` 菜单（及 0 入口空态）提供 **「上传文件」** 动作，弹窗调用 `mode: 'attach_version'`，上传成功后直接挂到该版本且**不升版本号**。

### 8.4 四级槽位与资源列表的 R2 展示
